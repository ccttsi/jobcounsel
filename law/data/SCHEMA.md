# 직업상담 법전 — 데이터 스키마

`law/data/laws.json` 하나를 화면이 읽는다. 아카이브(법령·조례 전문 수집)가 끝나면 **이 파일만 갈아 끼우거나 샤드를 더하면** 검색·책 보기가 그대로 전체 법령·조례 위에서 동작하도록 만든 계약이다.
화면 코드에는 법령 이름·개수를 적지 않는다. 모든 목록·개수는 이 파일에서 센다.

## 1. 파일 구성

| 파일 | 내용 | 지금 상태 |
|---|---|---|
| `laws.json` | 색인 + (지금은) 조문 전문. `kind: "index"` | ⭐ 우선참조 8건 · 조문 50개 |
| `shard-01.json` … | 조문 전문만 담는 조각. `laws.json`의 법령에 `"shard": "shard-01"`이 있을 때 화면이 그 법령을 열 때(또는 책 보기를 열 때) 불러온다 | 아직 없음 |

- `laws.json`이 1.5MB를 넘거나 법령이 100건을 넘으면 조문 전문을 `shard-NN.json`으로 나눈다. `laws.json`에는 `one_line`·`keywords`·`articles` 대신 `articleCount`·`shard`만 남겨도 검색은 동작한다(본문 검색은 샤드를 불러온 뒤 깊어진다).
- 샤드 파일 형식: `{ "laws": [ { "id": "...", "easy": [...], "examples": [...], "check": [...], "visual": {...}, "articles": [...] } ] }` — `id`로 본 파일과 이어 붙인다.
- 모든 경로는 `law/` 폴더 기준 상대 경로다.

## 2. 최상위

```json
{
  "version": "1.0.0",
  "updated": "2026-11-17",
  "kind": "index",
  "notice": { "rights": "…", "source": "…", "limit": "…" },
  "situations": [ … ],
  "laws": [ … ]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `version` | ✓ | 스키마·데이터 버전. 형식이 바뀌면 올린다 |
| `updated` | ✓ | 마지막 수집·검수 날짜(`YYYY-MM-DD`) |
| `kind` | ✓ | `"index"` |
| `notice.rights` | ✓ | 저작권 표기(법령·조례는 저작권법 제7조) |
| `notice.source` | ✓ | 원문 출처 |
| `notice.limit` | ✓ | 한계·면책(법률 자문 아님) |
| `situations` | ✓ | 상담 상황 키워드 사전(§4) |
| `laws` | ✓ | 법령·조례 목록(§3) |

## 3. 법령 한 건(`laws[]`)

```json
{
  "id": "job-security",
  "no": "01",
  "name": "직업안정법",
  "short": "직업안정법",
  "kind": "법률",
  "priority": true,
  "ministry": "고용노동부",
  "effective": "2024. 7. 24.",
  "promulgation": "법률 제20121호, 2024. 1. 23., 일부개정",
  "law_url": "https://www.law.go.kr/LSW/lsInfoR.do?lsiSeq=259231&efYd=20240724",
  "one_line": "직업소개소가 받을 수 있는 소개비의 상한과 …",
  "why": "소개비·인력사무소·헤드헌터 상담",
  "chips": ["소개비", "직업소개소"],
  "keywords": ["직업안정법", "소개요금", "…"],
  "easy": [{ "h": "소개비 상한은 법이 아니라 고시가 정합니다", "p": "…" }],
  "examples": [{ "scene": "…", "q": "내담자: …", "a": "상담사: …" }],
  "check": ["소개요금 서면 약정서가 있는가"],
  "visual": { "kind": "bars", "…": "…" },
  "articles": [{ "no": "제19조", "title": "유료직업소개사업", "paras": ["① …", "② …"] }]
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `id` | ✓ | 소문자·하이픈. 화면 주소(`#law=<id>`)와 샤드 연결에 쓴다. 한 번 정하면 바꾸지 않는다 |
| `no` | ✓ | 화면에 보이는 두 자리 번호(`"01"`). 순서 표시용 |
| `name` | ✓ | 법령·조례 정식 이름(공포된 이름 그대로) |
| `short` | ✓ | 목록·결과 한 줄에 쓰는 짧은 이름. 없으면 `name` |
| `kind` | ✓ | `법률` · `대통령령` · `고용노동부령` · `조례` · `규칙` · `고시` |
| `priority` | ✓ | `true`면 ⭐ 우선참조. 검색 정렬에서 동점일 때 앞선다 |
| `ministry` | ✓ | 소관 부처·지방자치단체 |
| `effective` | ✓ | 시행일(`YYYY. M. D.`) — 원문 머리말의 값 |
| `promulgation` | ✓ | 공포 번호·일자·개정 구분 |
| `law_url` | ✓ | law.go.kr 원문 주소. 조문별 닻(anchor)을 지어내지 않는다 |
| `one_line` | ✓ | 첫 화면 목록에 보이는 한 문장 |
| `why` | | 상담에서 언제 꺼내는지(`소개비·인력사무소 상담`) |
| `chips` | | 검색창 아래 상황 키워드로도 쓰는 이름표. `situations[].label`과 같은 말을 쓴다 |
| `keywords` | ✓ | 검색 동의어·줄임말·관련 낱말. **조문 본문에 없는 말도 여기에 넣어 검색되게 한다**(예: `알바`, `국취`) |
| `easy` | ✓ | 쉬운 풀이. `h`(소제목) + `p`(문단). 2~3개. 어려운 용어는 첫 문장에서 푼다 |
| `examples` | | 상담실 대화. `scene`(상황 한 줄) + `q`(내담자 발화) + `a`(상담사 답). 확인되지 않은 제도·금액을 말하지 않는다 |
| `check` | | 실무 체크리스트(짧은 질문) |
| `visual` | | §5. **없으면 `null` 또는 필드 생략** — 화면은 빈 칸을 만들지 않고 슬롯을 접는다 |
| `articles` | ✓ | §6. 조문 배열 |
| `shard` | | 조문 전문이 샤드에 있을 때 파일 이름(`"shard-01"`). `laws.json`에서 `articles`를 빼고 `articleCount`만 둔다 |

- 확인되지 않은 값은 **필드를 지어내지 않는다**. 값이 없으면 그 필드를 빼고, 화면은 그 줄을 그리지 않는다.
- 화면 문구에 법령 개수·조문 수를 고정으로 쓰지 않는다(배열 길이에서 센다).

## 4. 상담 상황 사전(`situations[]`)

```json
{
  "id": "s-fee",
  "label": "소개비",
  "terms": ["소개비", "소개요금", "인력사무소", "선급금"],
  "laws": [
    { "id": "job-security", "articles": ["제19조", "제21조의2", "제32조"] }
  ]
}
```

- `label`은 검색창 아래 칩으로 그대로 나온다(5~8개 권장).
- `terms`는 동의어·구어·줄임말. **검색어가 `terms`에 닿으면** 그 상황으로 보고, 연결된 `laws`를 결과 위로 올리며 `articles`를 결과 줄에 근거로 보여 준다.
- `laws[].id`는 반드시 `laws[]`에 있어야 한다. 없는 id는 화면이 조용히 건너뛴다.
- 상황 하나가 여러 법령을 가리켜도 된다(예: `면접 가족 질문` → 채용절차법 + 남녀고용평등법).

## 5. 가변형 시각자료(`visual`)

`kind` 하나로 모양이 정해지고, 화면은 **내용 높이에 맞춰 늘어난다**(고정 비율·빈 자리 없음). 없으면 슬롯 자체를 그리지 않는다. 색은 화면 토큰(`--acc`, `--ink`, `--muted`)만 쓰므로 밝게/어둡게가 자동으로 맞는다.

| `kind` | 필드 | 쓰는 곳 |
|---|---|---|
| `bars` | `unit`, `max`, `items[{label, value, note?}]`, `note?` | 비율·상한·금액 비교(소개요금 상한, 수습 감액) |
| `compare` | `left{head, items[]}`, `right{head, items[]}`, `note?` | O/X, 해도 되는 것/안 되는 것 |
| `flow` | `steps[{k, d}]`, `note?` | 절차·단계(수급 절차) |
| `timeline` | `items[{t, d}]`, `note?` | 기한·시간표(해고 예고·금품 청산) |

- 숫자는 원문·고시에 있는 값만 쓴다. 계산해 만든 값이면 `note`에 계산 근거를 적는다.
- 글자는 직접 쓰고, 외부 라이브러리·이미지를 쓰지 않는다(인라인 SVG·CSS 막대만).

## 6. 조문(`articles[]`)

```json
{ "no": "제19조", "title": "유료직업소개사업", "paras": ["① …", "② …"] }
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `no` | ✓ | `제19조`, `제4조의3`, `고시 I`, `조례` 처럼 원문 표기 |
| `title` | | 괄호 안 제목(`(유료직업소개사업)`의 안쪽). 없으면 빈 문자열 |
| `paras` | ✓ | 문단 배열. 항(①②③)과 호(1. 2. 3.) 단위로 끊는다 |
| `kind` | | 이 조문이 다른 법령·고시에서 온 경우(`시행령`, `고시`, `조례`) |
| `src` | | 그 출처 이름(예: `고용보험법 시행령`) |
| `link` | | 조문이 다른 문서에서 왔을 때의 원문 주소(없으면 법령의 `law_url`) |
| `trim` | | 원문에서 뺀 부분이 있으면 그 사실과 이유 |

- **글자는 원문 그대로.** 개정 연혁 표시(`<개정 …>`, `[전문개정 …]`, `<신설 …>`)만 읽기 쉽도록 뺀다. 그 사실은 `notice.rights`에 적는다.
- 조문을 요약해 `paras`에 넣지 않는다. 요약은 `easy`가 맡는다.
- 법령 전체를 다 싣지 않아도 된다. 상담에서 자주 찾는 조문만 골라 싣고, 그 사실을 `notice.limit`에 적는다.
- 조례·고시는 `kind`로 구분하고 `src`·`link`를 채운다. 한시 조항이 끝났으면 빼고 `trim`에 적는다.

## 7. 검색 규칙(화면 구현 계약)

1. 검색어를 공백으로 나눈 토큰이 **모두** 어딘가에 닿아야 결과에 남는다(AND).
2. 점수: 이름 일치 > `chips` > `keywords` > 상황 `terms` > `one_line` > 조문 제목 > 조문 본문.
3. 동점이면 `priority: true`가 앞, 그다음 `no` 순.
4. 결과 줄에는 **왜 걸렸는지**(상황 이름·맞은 조문)를 함께 보여 준다.
5. 입력은 한 프레임에 한 번만 다시 그린다(타이핑 지연 없이).

## 8. 검수 체크(데이터를 갈아 끼운 뒤)

- [ ] 모든 `laws[].id`가 유일하고 `situations[].laws[].id`가 실제로 존재하는가
- [ ] `law_url`이 law.go.kr 원문을 가리키고 200인가
- [ ] 조문 `paras`에 개정 연혁 표시(`<개정`)가 남아 있지 않은가
- [ ] `effective`·`promulgation`이 원문 머리말과 같은가
- [ ] 숫자(요율·기한·금액)가 원문·고시와 같은가, 계산값이면 `note`에 근거가 있는가
- [ ] `visual`이 없는 법령에서 화면에 빈 슬롯이 생기지 않는가
