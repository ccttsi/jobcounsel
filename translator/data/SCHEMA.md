# 내담자 언어 번역기 · 용어 데이터 계약 (`terms.json`)

26번 섹터 「내담자 언어 번역기」가 읽는 유일한 자료입니다. 화면(`app.js`)은 이 파일을 고치지 않고 읽기만 합니다.
용어를 더하거나 고칠 때는 이 파일만 바꾸면 목록·검색·쪽 나눔·연계 칩·묶음 필터의 숫자가 따라옵니다(개수는 화면이 셉니다).

```
translator/data/terms.json     client-language-translator v2.0.0 · 용어 625 · 묶음 43
```

## 1. 최상위

| 키 | 필수 | 설명 |
|---|---|---|
| `schema_version` | ✓ | `MAJOR.MINOR.PATCH` |
| `dataset` | ✓ | `client-language-translator` (고정) |
| `updated_at` | ✓ | `YYYY-MM-DD` — 화면 상세 바닥의 「기준일」 |
| `notice` | ✓ | 자료 성격 한 문단(화면 바닥글과 별개 기록) |
| `categories` | ✓ | 분야 6개. `id`·`name`·`short`·`desc` |
| `groups` | ✓ | 상위 묶음. `id`·`cat`·`name`·`short` |
| `banNotice` | ✓ | `forbid`·`care` 두 금지 수준의 안내 문장 |
| `sources` | ✓ | 출처 목록. `id`·`name`·`url`(https)·`note` |
| `terms` | ✓ | 용어 배열(아래) |

## 2. 분야(`cat`)

| id | 이름 | 무엇을 담나 |
|---|---|---|
| `job` | 직무·업무 | 직업군별 업무 약어와 직무 용어(MES·KPI·결산 등) |
| `industry` | 산업·현장 | 산업·생산·기술 현장의 용어(FAB·수율·GMP 등) |
| `edu` | 학력·자격 | 학위·전공·자격 제도(학점은행제·기사·NCS 등) |
| `policy` | 고용제도 | 고용제도·지원금·상담 현장 용어(국취·소정급여일수 등) |
| `slang` | 은어·치환어 | 현업·취준생이 전문용어를 줄이거나 바꿔 부르는 말(취뽀·물경력·칼퇴 등) |
| `derog` | 속어·비하표현 | 내담자가 자기 처지·직업·학력을 낮춰 부를 때 쓰는 말(노예·지잡대·꼰대 등) |

분야를 더하면 `categories`에 한 줄 넣고, 화면 탭은 배열 길이에서 셉니다(코드에 6을 고정하지 않음).

## 3. 상위 묶음(`groups`)

- `id`는 영문 소문자·하이픈. `cat`은 `categories`의 분야 id. `name`은 화면의 경로 표기, `short`는 목록 배지·필터 칩에 쓰는 짧은 이름.
- 용어는 반드시 자기 분야의 묶음 하나에 속합니다(`grp`). 분야와 묶음의 `cat`이 다르면 검사에서 실패합니다.
- 묶음은 분야 탭을 눌렀을 때만 2단 필터로 열립니다(`전체` + 그 분야의 묶음). 휴대폰은 한 줄 가로 스크롤, 큰 화면은 여러 줄.

| 분야 | 묶음 |
|---|---|
| 직무·업무 | IT·개발/데이터 · 생산·제조/품질 · 경영·인사/총무 · 영업·마케팅/MD · 금융·회계/세무 · 디자인·콘텐츠 · 물류·유통/구매 · 연구개발·인증 · 서비스·고객상담 · 보건·의료/간호 |
| 산업·현장 | 반도체·전자 FAB · 바이오·제약/GMP · 자동차·모빌리티 · 건설·플랜트 · IT·플랫폼/스타트업 · 유통·리테일 · 공공·공기업 · 에너지·화학 · 식품·외식 · 생산·품질/안전 |
| 학력·자격 | 공학·자연계열 · 상경·경영계열 · 인문·사회계열 · 보건·간호/복지 · 국가기술자격·전문자격 · 직업훈련·국비과정 · 학위·학점 대안 경로 |
| 고용제도 | 고용보험·실업급여 · 국민취업지원제도 · 훈련·내일배움카드 · 대상별 사업 · 근로조건·노동관계 · 지원금·장려금 |
| 은어·치환어 | 취업준비·채용 · 회사·조직생활 · 보상·근무조건 · 공부·스펙 · 직업군별 현장 은어 |
| 속어·비하표현 | 신분·처지 비하 · 학력·출신 비하 · 직업·업종 비하 · 사람·태도 비하 · 자조·자책 |

## 4. 용어 한 건

| 키 | 필수 | 규칙 |
|---|---|---|
| `id` | ✓ | 영문 소문자·숫자·`_`. 주소 `#t=<id>`의 열쇠. **중복 금지** |
| `term` | ✓ | 내담자가 실제로 말하는 표기(약어는 영문 그대로) |
| `full` | ✓ | 영문 원어. 우리말 표기만 있는 말은 한글 명칭 |
| `ko` | ✓ | 한글 정식 명칭(또는 쉬운 우리말) |
| `cat` | ✓ | 위 분야 id |
| `grp` | ✓ | 위 묶음 id(같은 분야의 묶음이어야 함) |
| `easy` | ✓ | 한 줄 쉬운 뜻. **90자 이내**. 초임 상담사가 바로 알아듣는 말로 |
| `ctx` | ✓ | 「내담자가 이 말을 했다면 실제로 했을 일」. **130자 이내**, 추정은 「가능성이 큽니다」로 |
| `qs` | ✓ | 상담사가 이어 물을 질문 1~3개(보통 2개) |
| `links` | ✓ | 연계 자료 1~3개. `{ "to": 섹터 id, "q": 검색어 }` |
| `src` | – | `sources`의 id, 또는 `null` |
| `aka` | – | 같은 말의 다른 표기(검색용). 배열 |
| `ban` | – | `forbid`(상담사 사용 금지) 또는 `care`(따라 쓰지 않기). 없으면 일반 용어 |
| `swap` | `ban`이 있으면 ✓ | 상담사가 대신 쓸 중립 표현 1~3개 |
| `say` | `ban`이 있으면 ✓ | 내담자의 말을 중립적으로 되받는 응답 예 한 문장 |
| `note` | – | 보충 한 줄(선택) |

- **`src`가 `null`이면** 화면은 「공식 정의를 붙이지 않은 말입니다 — 업계에서 통용되는 약어·표현이라 기관 문서의 정의를 확인하지 않았습니다」로 적습니다. 지어낸 출처를 붙이지 않습니다.
- `qs`는 정답을 확인하는 질문이 아니라 **경력을 사실로 바꾸는 질문**입니다(“무엇을 했나요”보다 “어떤 화면을 썼나요”).
- `ban: forbid`는 「상담사 사용 금지」, `care`는 「따라 쓰지 않기」로 화면에 나옵니다. 두 경우 모두 상세 카드 **우상단에 딱지**가 붙고, 본문 맨 앞에 `banNotice` 안내와 `swap`·`say`가 열립니다.
- 속어·비하표현(`derog`) 용어는 전부 `ban`을 가집니다.

## 5. 연계 링크(`links[]`)

`to`는 `assets/tools.js`의 섹터 id 가운데 하나여야 합니다. `q`는 그 섹터의 검색어입니다.

| 섹터 | 주소 꼴 | 비고 |
|---|---|---|
| `taxonomy` · `company` · `thermometer` · `emerging` · `decalcomania` · `univ` · `grad` | `../<섹터>/?q=<검색어>` | 그 섹터가 `?q=`를 받습니다 |
| `cert` | `../cert/#list?q=<검색어>` | 자격증 도감은 주소(hash)로 찾습니다 |
| `law` · `manual` · `hud` · `transit` · `talk` · `reality` · `portals` · `surgery` · `interview` · `portfolio` · `theory` · `vpi` · `parsons` · `library` · `labor` · `briefing` · `dacum` | `../<섹터>/` | `?q=`를 받지 않으므로 섹터 첫 화면으로 |

- `q`는 **그 섹터 자료에 실제로 있는 이름**이어야 합니다(없으면 빈 결과가 열립니다). 자격증이면 종목 이름, 직무분류면 NCS·KECO·KSCO·직업 이름, 산업 온도계면 산업 이름.
- 한 용어에 링크를 3개 넘기지 않습니다(카드가 길어지고 휴대폰 한 장이 넘칩니다).

## 6. 저작권·사실 원칙 (이 자료에서 지킨 것)

- 풀이(`easy`·`ctx`·`qs`·`swap`·`say`)는 **자료실이 새로 쓴 글**입니다. 기관 문서·사전·블로그·커뮤니티 글의 문장을 옮기지 않았습니다.
- 기관 문서(법령·고시·공공데이터)의 **사실·수치만** 확인해 우리말로 다시 썼습니다. 조문은 저작권법 제7조에 따라 보호 대상이 아닙니다.
- 은어·속어는 블라인드·에브리타임 같은 공개 커뮤니티와 직업군별 공개 게시판에서 **통용되는 뜻과 맥락만** 확인해 새로 풀었습니다. 특정 게시글의 문장·사례를 옮기지 않았고, 개인을 특정할 수 있는 내용은 싣지 않았습니다.
- 제도·금액은 **기준일(2026-11-19)** 값이며, 같은 저장소의 `hud`·`manual`·`transit` 자료와 맞췄습니다(구직촉진수당 월 60만원·소정급여일수 120~270일 등).
- 확인하지 못한 값은 **쓰지 않습니다.** 연령·비율·금액이 기관마다 달라지는 말(신중년 등)은 범위를 단정하지 않고 「기관마다 조금씩 다르다」로 적습니다.
- 업계 약어는 **공식 정의가 없다는 사실을 밝히고** 출처를 비웁니다. NCS 출처는 정의문이 아니라 **그 말이 속한 직무 영역(능력단위·KSA)** 의 근거입니다.
- 비하·속어는 **내담자의 말을 이해하기 위한 참고용**이며, 상담사가 먼저 쓰거나 따라 쓰지 않도록 금지 딱지와 중립 치환 표현을 함께 둡니다. 비하의 대상이 된 사람을 낮추는 방식으로 풀이하지 않습니다.

## 7. 검사

`ops/scripts/validate_repo.py`의 `check_terms()`가 배포 전에 아래를 봅니다.

- 필수 키·자료형, `cat` 값, `id` 중복, `qs` 1~3개, `links` 1~3개
- `groups`의 id 중복·`cat` 유효성, 용어 `grp`가 같은 분야의 묶음인지
- `links[].to`가 `assets/tools.js`의 섹터 id인지(오타로 죽은 칩이 나가지 않게)
- `src`가 `sources`에 있는지, `sources[].url`이 https인지
- `easy` 90자·`ctx` 130자 상한
- `ban` 값과, `ban`이 있으면 `swap`·`say`가 있는지
- 분야별·전체 개수와 `data-count`가 맞는지(화면은 세지만, 계약 위반을 배포 전에 잡기 위해)
