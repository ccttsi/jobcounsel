# AUP-8 피드백 고리 — 설계 (2026-11-27)

> MCL Goal · AUP(비서 고도화) 하부계획 AUP-8. 답마다 👍/👎를 받아 **익명으로** 모으고,
> 매주 «어느 유형·어느 자료에서 답이 약한가»를 뽑아 성적표(AUP-2) 보강 후보로 돌린다.
> 헌법 제3조(유출·개인정보)가 설계의 첫 조건이다.

## 1. 무엇을 남기고, 무엇을 남기지 않는가

| 남긴다 (한 평가 = 한 줄) | 남기지 않는다 |
|---|---|
| `day` 날짜(시각 없음) | 질문 문장 · 답 문장 · 검색어 |
| `vote` 👍 1 / 👎 -1 | 사용자 번호(user_id)·아이디·세션 |
| `qtype` 질문 유형(계산·제도·안내·상담 진행 — 서버가 판정한 값) | 대화방·메시지 번호 |
| `sectors` 답이 인용한 섹터 id(최대 3) | 시각(분·초) · IP · 기기 정보 |
| `reason` 👎 이유 — 정해진 네 가지 중 하나(틀림·엉뚱함·어려움·김), 자유 입력 없음 | 자유 의견 칸 |
| `mode`·`websearch`·`followup`(앞 질문이 있었나)·`fixed`(답 검사기가 고쳤나)·`model` | |
| `fid` 브라우저가 평가마다 새로 만든 무작위 번호(바꾸기·취소용, 사용자와 무관) | |

- 평가 줄과 사용자를 잇는 열쇠가 표 안에 **없다**. 하루 상한을 세는 칸(`jc_assistant_feedback_quota`)은
  «사용자·날짜·횟수»만 두고 평가 줄과 연결하지 않는다(외래키·공통 번호 없음).
- 90일이 지난 평가 줄은 쓰기 함수가 부를 때 함께 지운다(따로 도는 청소 작업 없음). 하루 상한 칸은 2일 뒤 지운다.

## 2. 켜고 끄기

- **기본 꺼짐.** 비서 «내 키» 탭의 「답 평가 단추 보이기」를 켠 사람에게만 답 밑에 👍/👎가 나온다
  (이 선택은 그 브라우저에만 — `localStorage`, 다시 끌 수 있음).
- 로그인한 사용자만(비서 질문 자체가 로그인 필요). 한 사람 하루 60회 상한.
- 같은 답을 다시 누르면 바뀌거나(👍↔👎) 취소된다 — `fid`로 그 줄만 고치거나 지운다.

## 3. 길 (어디를 거치는가)

```
답 밑 👍/👎 (assets/assistant.js) ── action:'feedback' ──▶ assistant-proxy(index.ts)
     세션 확인 → 하루 상한(jc_assistant_feedback_take) → 칸 검사(흰 목록) → jc_assistant_feedback_put
                                                              │
매주 월 (feedback-weekly.yml) ── Management API SQL ──▶ jc_assistant_feedback_week(7)
     → «유형 × 섹터» 묶음별 평가 수·👎 비율·이유 → Actions 요약 + 노션 진행일지 한 줄 + 산출물(JSON)
     → 평가 3건 이상·👎 40% 이상 묶음 = «성적표 보강 후보»
```

- 표 두 개는 RLS를 켜고 anon·authenticated 권한을 전부 회수한다. 읽고 쓰는 길은 Service Role 함수(서버)와
  집계 함수(관리 토큰)뿐이다 — 기존 `jc_assistant_*` 표와 같은 규칙.
- 서버는 `qtype`을 답할 때 이미 판정한다(AUP-6 `QTYPE.check`) → 응답에 `qtype`을 실어 화면이 평가에 되돌려 보낸다.
  화면이 보낸 값은 흰 목록(`calc·policy·guide·counsel`)으로 다시 거른다.

## 4. 이 고리가 만들지 않는 것

- **문답집(FTN-1) 원문.** 질문·답 문장을 남기지 않으므로 이 고리만으로는 학습 문장이 생기지 않는다.
  «약한 유형·섹터 목록»이 성적표 문항 보강과 FTN-1 문답집을 «어디부터 쓸지» 정하는 지도가 된다.
- 사용자별 화면·통계. 관리 화면(`/admin/`)에 붙이는 것은 다음 단계 후보(집계만).
