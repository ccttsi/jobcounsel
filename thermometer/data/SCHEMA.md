# SCHEMA.md — 16번 산업 온도계 데이터 계약 (v1.0.0)

`thermometer/`는 세 파일을 사람이 관리하고, 한 파일을 스크립트가 만든다. 화면은 **`thermometer.json` 하나만 읽는다**.

| 파일 | 누가 | 무엇 |
|---|---|---|
| `sources.json` | 사람 | 출처 16곳. 라이선스·기준시점·Track(A/B)·쓰임 |
| `industries.json` | 사람 | 산업 24개. KSIC 자리·체감 갈래·규모·한 줄 설명 |
| `indicators.json` | 사람 | 산업 × 국내/글로벌 × 4축의 근거 수치 |
| `build_thermometer.py` | — | 검증 → 축 점수 → 온도 → `thermometer.json` |
| `thermometer.json` | 스크립트 | 화면이 읽는 완성본 (손으로 고치지 않는다) |

```bash
python3 thermometer/data/build_thermometer.py           # 검증 + 산출
python3 thermometer/data/build_thermometer.py --check   # 검증만
```

---

## 1. 온도는 무엇을 재는가

**같은 산업을 두 번 잰다 — 국내(한국)와 글로벌.** 두 온도의 차이가 이 도구의 답이다.
한 산업의 온도는 **네 축의 공식 수치**로만 만든다. 축마다 근거가 0~2개 실린다.

| 축 | 무엇을 보는가 | 국내 근거 | 글로벌 근거 |
|---|---|---|---|
| `emp` 고용 | 사람을 얼마나 쓰는가 | 사업체노동력조사 종사자 수(전년동월비) | 미국 BLS 산업별 고용(전년동월비) |
| `prod` 산업규모·생산 | 실물이 얼마나 나오는가 | 광공업·서비스업 생산지수(전년동월비) | 업종 국제기구 지표(SIA·worldsteel·Clarksons·IEA) |
| `rev` 매출·수익 | 돈이 얼마나 들어오는가 | 한국은행 업종별 매출액증가율(2025) | 국제 가격지수(FAO·EIA 브렌트유) |
| `trend` 트렌드·수요 | 앞으로 늘어나는가 | 20대 품목 수출·소매판매·건설수주(전년동월비) | 시장 전망(WSTS·IEA·SIPRI·UNWTO) |

**축마다 자료의 기준시점이 다르다.** 그래서 축 점수 옆에 언제 자료인지(`period`)를 반드시 함께 보여 준다.
2026년 9월 생산지수와 2025년 연간 매출액은 같은 달의 값이 아니다 — 섞어서 "이번 달"이라고 말하지 않는다.

## 2. 근거 하나의 모양

```json
{
  "label": "반도체 생산지수",
  "yoy": 10.3,                     // 전년(동월·동기) 대비 % — 계산에 쓰는 유일한 값
  "value": "240.2 (2020=100)",     // 화면에 그대로 보이는 값
  "period": "2026-09",             // 자료의 기준시점
  "source_id": "src_kostat_ia_2609",
  "note": "전년동월비. 광공업 업종별 생산",
  "dir": 1                          // 1 = 오르면 더움, -1 = 오르면 추움(원가 부담 등)
}
```

- `yoy`가 없는 근거는 싣지 않는다. 지수 **수준**만 있고 전년비가 없는 값은 `info`(참고)로 내린다.
- `dir: -1`은 "올라도 산업에는 부담"인 지표에만 쓴다(예: 나프타 원료가 되는 브렌트유, 에너지 수입액).
- 확인되지 않은 값은 **0으로 채우지 않고 항목을 통째로 비운다.** `value`를 모르면 그 근거를 빼고, 그 축이 비면 축 점수도 비운다.

## 3. 계산식 (스크립트와 같은 식)

눈금(`baseline`) — "이 정도면 확실히 뜨겁다"고 보는 전년비.

| 축 | 눈금 | 뜻 |
|---|---|---|
| 고용 | 3% | 3% 늘면 사람을 뽑는 산업 |
| 생산 | 5% | 5% 늘면 실물이 도는 산업 |
| 매출 | 5% | 5% 늘면 돈이 도는 산업 |
| 트렌드 | 15% | 15% 늘면 수요가 새로 생기는 산업 |

가중치 — 고용 0.30 · 생산 0.30 · 매출 0.20 · 트렌드 0.20.

```
① 근거 하나   ratio = yoy ÷ 눈금
              s     = tanh(ratio) × dir
② 축 점수     S(축)  = 그 축 근거들의 평균          (근거가 없으면 그 축은 없음)
③ 종합        H     = Σ(가중치 × S) ÷ Σ(가중치)      (실린 축만)
              H    *= √(실린 가중치 합)             ← 근거가 적으면 온도도 덜 믿는다
④ 온도        T     = H × 40  (H ≥ 0, 폭염까지)
              T     = H × 20  (H <  0, 한파까지)     → -20.0 ~ +40.0℃
```

- **tanh를 쓰는 이유**: 눈금의 1배면 0.76, 2배면 0.96, 3배면 0.995로 1에 가까워질 뿐 넘지 않는다. 그냥 잘라 버리면(clamp) 큰 산업이 전부 +1에 몰려 서로 구별되지 않는다.
- **√(커버리지)를 곱하는 이유**: 근거가 1축뿐이면 그 온도도 55%만 믿는다. 적게 아는 산업이 극단으로 튀지 않게.
- **말(밴드)**: 2축 이상일 때만 붙인다. 20℃ 이상 폭염 · 8℃ 이상 더움 · 2℃ 초과 따뜻함 · -2~2℃ 평년 · -8℃ 초과 서늘 · -14℃ 초과 추움 · 그 아래 한파. **1축뿐이면 "근거 1축"**이라고 적고 밴드를 붙이지 않는다.
- `axes_used`(몇 축으로 냈는지)와 `weight_covered`를 항상 함께 저장한다. 화면은 "근거 4/4"처럼 보여 준다.

## 4. 산업 한 칸의 모양 (`thermometer.json`)

```json
{
  "id": "semicon", "name": "반도체",
  "ksic": {"major": "C", "major_name": "제조업", "code": "C261", "mid": "261 반도체 제조업"},
  "feel": {"group_id": "fg-chip", "group": "첨단·정밀 제조", "name": "반도체"},
  "size": {"value": 169450, "unit": "명", "period": "2026-04", "label": "반도체 제조업 종사자", "source_id": "src_moel_lfs_2609"},
  "domestic": {
    "axes": {"emp": {"score": 0.55, "items": [ ... ]}, "prod": {...}, "rev": {...}, "trend": {...}},
    "composite": 0.86, "temperature": 34.6, "band": "폭염", "band_raw": "폭염",
    "axes_used": 4, "axes_total": 4, "weight_covered": 1.0, "rank": 1
  },
  "global": {"...": "같은 모양"},
  "gap": 5.1,                 // 국내 − 글로벌 (양수면 국내가 더 뜨겁다)
  "info": [ {"label": "...", "value": "...", "period": "...", "source_id": "..."} ]
}
```

- `rank`는 **국내 온도** 높은 순이다(온도순 정렬의 기본값). 온도가 없는 산업은 `null`.
- `info`는 계산에 넣지 않은 참고 수치(신조선가지수·DDR5 고정가·브렌트유 등)다. 출처·기준시점은 같게 단다.

## 5. 두 갈래 분류 (`classifications`)

화면 위 토글이 같은 24개 산업을 두 방식으로 늘어놓는다. **산업 데이터는 한 벌뿐이고, 묶는 방식만 바뀐다.**

- **표준산업분류(KSIC) 정석** — 제11차 KSIC 대분류(C·J·K·G·H·F·L·Q·P·I·D) 아래 `ksic.code`·`ksic.mid` 순서로 묶는다. 이 자료실이 다루는 산업만 싣고, 전 분류를 옮겨 적지 않는다.
- **구직자 체감 산업군** — `feel.group`(첨단·정밀 제조 / 소재·장치 / 모빌리티 / 생활·소비 / 디지털 / 금융·부동산 / 사회 기반 / 에너지)으로 묶는다. 같은 산업의 이름도 `feel.name`을 쓴다(예: `C30 자동차 및 트레일러 제조업` ↔ `자동차·부품`).
- 코드가 정확히 하나로 떨어지지 않는 산업(석유화학 = C19+C20, 콘텐츠 = J59+J60)은 `code`에 둘 다 적고 `mid`에 근거를 남긴다. **임의로 한 코드에 끼워 맞추지 않는다.**

## 6. 저작권·사실 검증 규칙 (이 데이터의 제1원칙)

1. **공식·공개 자료만** 쓴다 — 국가데이터처·고용노동부·한국은행·산업통상부, 미국 BLS·EIA, SIA/WSTS·worldsteel·FAO·UNWTO·SIPRI·OICA·IEA.
2. **Track A**(재가공 허락: 공공누리 1·2유형, 미국 연방정부 저작물)는 출처를 표시하고 수치를 인용한다.
   **Track B**(보도자료·민간 조사기관)는 **사실과 수치만** 인용하고 문장·표·그림을 옮기지 않는다. 화면에는 출처 이름과 원문 링크만 둔다.
3. 모든 수치에 `period`(기준시점)를 단다. 기준시점 없는 수치는 싣지 않는다.
4. 확인되지 않은 값은 **지어내지도, 0으로 채우지도 않는다.** 항목을 빼고, 축이 비면 온도에서도 뺀다. 화면은 그 사실을 "근거 없음"으로 보여 준다.
5. 민간 잡포털·블로그를 출처로 쓰지 않는다. 보도로만 확인할 수 있는 민간 집계(클락슨 신조선가 등)는 `sources.json`의 `usage`에 "보도로 확인"이라고 적는다.
6. 출처를 늘리거나 바꾸면 `sources.json`의 `license.verified_at`을 갱신하고 `build_thermometer.py --check`를 다시 돌린다.

---

## 7. 새 산업을 넣을 때

1. `industries.json`에 한 칸(id·KSIC 자리·체감 갈래·규모·한 줄 설명)을 더한다.
2. `indicators.json`에 국내·글로벌 4축을 채운다. **최소 2축**은 채워야 온도가 의미를 가진다(1축이면 화면이 "근거 1축"이라고 밝힌다).
3. `build_thermometer.py`를 돌린다. 검증 실패(출처 없음·period 없음·yoy 없음)는 그 자리에서 막힌다.
4. 화면은 `thermometer.json`만 읽으므로 HTML·JS를 고치지 않아도 새 산업이 뜬다. 섹터 장부(`assets/tools.js`)의 문구만 손본다.
