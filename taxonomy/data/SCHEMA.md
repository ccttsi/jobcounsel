# SCHEMA.md — 18번 3대 분류 교차 사전 데이터 계약

이 문서는 `taxonomy/data/taxonomy.json`을 화면(`/taxonomy/`)으로 구현하는 클로드 코드가 읽는 **계약서**다.
데이터는 피클(공공데이터 수집·정규화)이 만들고, 화면 코드는 클로드가 쓴다(`ops/ROLES.md`).

- 파일: `taxonomy/data/taxonomy.json` (UTF-8, JSON, 약 3.6MB)
- 배포 주소: `https://ccttsi.github.io/jobcounsel/taxonomy/data/taxonomy.json`
- 스키마 버전: `meta.schema_version = "1.0"` (2026-11-16 기준)
- 검증: `python3 taxonomy/data/validate.py` → **오류 0건** 통과본만 배포한다.

---

## 0. 이 데이터로 무엇을 하는가

NCS(국가직무능력표준) · KECO(한국고용직업분류) · KSCO(한국표준직업분류)를 한 화면에서 잇는다.

1. **계층 탐색** — 각 분류의 대분류 → 중분류 → 소분류 → 세분류(→ KSCO 세세분류) 트리
2. **검색** — 코드·명칭 부분일치로 세 분류를 동시에 찾기
3. **역추적** — KSCO 코드 하나에서 KECO → NCS(소분류) → 능력단위까지 거슬러 올라가기
4. **직업 단위 교차** — KONET 직업 6,713건이 KECO·KSCO 코드를 동시에 갖고 있어, "이 직업은 세 분류에서 각각 무엇인가"를 한 줄로 보여 줄 수 있다.

> 학습·실습용 참고 자료다. 분류 간 연결은 **공식 매핑 파일에 실제로 적힌 것만** 담았다. 없는 연결을 추정해 채우지 않았으므로, 연결이 비어 있는 것은 "자료 없음"이지 "관계 없음"이 아니다.

## 1. 최상위 구조

```json
{
  "meta":     { "schema_version", "dataset", "sector", "generated_at", "repository", "notice",
                "counts", "coverage", "corrections", "level_keys" },
  "sources":  [ { "id", "name", "dataset_id", "publisher", "license", "url", "file",
                  "base_date", "used_for", "rows" } ],
  "ncs":      { "notice", "levels": { "major","middle","minor","sub" }, "units": [], "legacy": [] },
  "keco":     { "version", "levels": { "major","middle","minor","sub" } },
  "ksco":     { "version", "levels": { "major","middle","minor","sub","detail" } },
  "mappings": { "ncs_keco": [], "ncs_training": [], "keco_ksco": [] },
  "jobs":     [ { "konet", "name", "keco_code", "ksco_code", "ksic_codes" } ]
}
```

`meta.level_keys`에 각 분류의 레벨 키와 한글 이름 대응이 들어 있다. 화면 라벨은 이 값을 쓰면 된다.

## 2. 분류 트리 (`ncs.levels`, `keco.levels`, `ksco.levels`)

모든 레벨은 **같은 모양의 노드 배열**이다.

```json
{ "code": "010101", "name": "프로젝트관리", "parent": "0101" }
```

| 필드 | 형 | 설명 |
|---|---|---|
| `code` | string | 분류 코드. **문자열**이다(앞자리 0 유지, KSCO `A` 포함). 숫자로 캐스팅하지 말 것 |
| `name` | string | 공식 명칭. 접두 번호(`01. `)는 제거된 상태 |
| `parent` | string \| 없음 | 바로 위 레벨의 `code`. 최상위(대분류)에는 이 키가 없다 |

- 부모는 **코드 접두**로 결정된다: NCS `01 → 0101 → 010101 → 01010101`, KECO `0 → 01 → 011 → 0111`, KSCO `1 → 11 → 111 → 1111 → 11111`. KSCO 군인 계열은 `A → A0 → A09 → A090 → A0900`처럼 문자로 시작한다.
- 트리 렌더링은 `parent`로 자식을 묶으면 되고, 별도 children 배열은 없다(파일 크기 때문에 중복 저장하지 않음).

### 2-1. 레벨 키 ↔ 한글

| 분류 | 레벨 키 | 한글 | 건수 |
|---|---|---|---|
| NCS | `major` | 대분류 | 24 |
| NCS | `middle` | 중분류 | 81 |
| NCS | `minor` | 소분류 | 270 |
| NCS | `sub` | 세분류 | 1,096 |
| KECO | `major` | 대분류 | 10 |
| KECO | `middle` | 중분류 | 35 |
| KECO | `minor` | 소분류 | 140 |
| KECO | `sub` | 세분류 | 495 |
| KSCO | `major` | 대분류 | 10 |
| KSCO | `middle` | 중분류 | 57 |
| KSCO | `minor` | 소분류 | 167 |
| KSCO | `sub` | 세분류 | 495 |
| KSCO | `detail` | 세세분류 | 1,270 |

### 2-2. NCS 능력단위 (`ncs.units`)

```json
{ "code": "0101010101_17v2", "code10": "0101010101", "version": "17v2",
  "name": "공적개발원조사업 개발전략수립", "level": 7, "hours": 80,
  "subs": ["01010101"], "in_notice": true, "sub_link": "notice" }
```

| 필드 | 설명 |
|---|---|
| `code` | 능력단위 분류번호(10자리 + `_` + 차수). **고유 키** |
| `code10` | 앞 10자리. `code10[0:2]=대분류`, `[0:4]=중분류`, `[0:6]=소분류`, `[0:8]=세분류` |
| `version` | NCS 개정 차수 표기(`17v2` 등) |
| `name` | 능력단위 명칭 |
| `level` | NCS 수준 1~8 (없으면 `null`) |
| `hours` | 표준 훈련시간 (없으면 `null`) |
| `subs` | 이 능력단위가 속한 세분류 코드 배열. 한 능력단위가 여러 세분류에 공통으로 들어가는 경우가 있어 **배열**이다 |
| `in_notice` | `true` = 2025-12-16 고시 별표에 실린 능력단위. `false` = 능력단위 정보 파일에만 있는 것 |
| `sub_link` | `"notice"` = 고시 별표가 밝힌 연결, `"code"` = 별표에 없어 분류번호 앞 8자리로 이은 연결, `null` = 연결 없음 |

총 **13,442건** (별표 연결 13,296 / 분류번호 연결 146 / 연결 없음 0).

### 2-3. NCS `legacy` — 현행 고시에 없는 코드 17건

매핑 파일에는 남아 있지만 2025년 고시 별표에서 빠진 NCS 코드다(`190301 가전기기개발` 계열 4개 소분류 + 13개 세분류).

```json
{ "code": "190301", "name": "가전기기개발", "level": "minor", "parent": "1903",
  "in_notice": false, "source": "s1" }
```

- 화면에서 **"현행 NCS 고시에 없음" 배지**로 구분해 보여 준다. 트리에 섞어 넣더라도 현행 270/1,096 건수와 합산하지 않는다.
- 매핑 조회 시 `levels.minor`/`levels.sub`에 없으면 `legacy`에서 찾는다.

## 3. 매핑 테이블 (`mappings`)

이름은 **코드만** 담는다. 명칭은 항상 2번의 분류 트리에서 조인한다(중복 저장 금지).

### 3-1. `ncs_keco` — NCS 소분류 ↔ KECO 세분류 (365쌍)

```json
{ "ncs_code": "020102", "ncs_level": "minor", "keco_code": "0241",
  "ncs_in_notice": true, "source": "s1" }
```

- **연결 레벨은 소분류(6자리)–KECO 세분류(4자리) 하나뿐이다.** 원자료의 8자리 NCS 행에는 KECO 코드가 비어 있다. 세분류 단위 NCS↔KECO 연결을 화면에서 만들지 말 것.
- **1:N**이다. NCS 소분류 하나에 KECO 세분류 여러 개가 붙고(최대 20개), 반대도 된다. 그래서 쌍 단위 행으로 저장했다.
- 커버리지: NCS 소분류 **97개**(현행 고시 93 + legacy 4) / KECO 세분류 **144개** (495개 중). 원자료가 이만큼만 매핑한다 — 나머지는 "매핑 자료 없음"으로 표시한다.

### 3-2. `ncs_training` — NCS ↔ 국가기간·전략산업직종 (1,160쌍)

```json
{ "ncs_code": "020102", "training_code": "1000188",
  "training_name": "공공디자인", "ncs_in_notice": true, "source": "s1" }
```

훈련직종 코드(7자리)는 다른 분류에 없으므로 이름을 함께 담았다. 부가 정보로만 쓰고 메인 3분류 축에는 넣지 않는다.

### 3-3. `keco_ksco` — KECO 세분류 ↔ KSCO 세분류 (479쌍)

```json
{ "keco_code": "0111", "ksco_code": "1111", "source": "s2" }
```

- 1:1로 정리된 쌍이다(KECO 479개 ↔ KSCO 479개). 나머지 KECO 세분류 16개는 원자료에 KSCO가 비어 있어 **행이 없다**.
- 원자료는 KONET 직업 6,713건을 통해 얻은 연결이므로, 같은 쌍이 여러 번 나오면 한 번만 남겼다.

## 4. 직업 (`jobs`) — KONET 직업 6,713건

```json
{ "konet": "K000001086", "name": "헬리콥터조종사", "keco_code": "6211",
  "ksco_code": "2381", "ksic_codes": ["H511", "H512"] }
```

| 필드 | 설명 |
|---|---|
| `konet` | 고용24·임금직업포털 직업코드(고유) |
| `name` | 직업명 |
| `keco_code` | KECO 세분류 코드(항상 있음) |
| `ksco_code` | KSCO 세분류 코드. 원자료 공란이면 `null` (6,713건 중 6,320건 있음) |
| `ksic_codes` | 주요 산업분류 코드 배열. `null` 가능. 화면에서는 참고용 |

**18-1(커리어넷 직업백과 500+ 상세)이 붙는 자리다.** 18-1 데이터는 `keco_code`·`ksco_code` 두 키로 이 `jobs`에 조인한다. 그때 `jobs` 배열에 `summary`, `tasks`, `certificates` 같은 키를 추가하고 `meta.schema_version`을 올린다(기존 키는 바꾸지 않는다).

## 6. 화면 구현 계약 (클로드 코드)

출처: `ops/ROLES.md` 「화면을 만들 때 꼭 지킬 것」, `DESIGN.md` §0(지재권 가드레일) · §1(4대 원칙).

- **화면 코드만 쓴다.** 데이터 수집·API 호출을 정적 앱 코드에 넣지 않는다. `taxonomy.json`은 정적 파일로 읽는다.
- **내보내기 금지** — 저장·인쇄·PDF·복사 버튼을 만들지 않는다(HTML 저장, `window.print`, 클립보드 API 모두 금지).
- **무의미한 세로 스크롤 금지** — 큰 화면 **1.5화면 이내**, 휴대폰(390px) **2.5화면 이내**. 목록+상세 2단, 탭, 아래에서 올라오는 시트로 해결한다(무한 스크롤 금지).
- **접기 기준선 900px**, 터치 대상 **44px 이상**, 가로 넘침 0, `env(safe-area-inset-*)` 존중.
- 모션은 `transform`·`opacity`만. `prefers-reduced-motion`에서 끈다.
- 대비·색·타이포는 `DESIGN.md` §3 토큰을 쓴다. 이 섹터만의 강조색 하나를 정해 쓰되 AI 템플릿 느낌(보라 그라데이션·유리 카드)은 금지.
- 특정 서비스 화면을 닮게 만들지 않는다(§0-1). 흔한 UI 관습(탭·아코디언·시트)만 쓴다.
- 첫 화면에 **"로그인 없이 사용 · 참고·실습용 자료"** 키워드를 노출한다.
- 모든 화면에 **"공식 매핑 자료에 있는 연결만 표시"** 안내를 한 줄로 둔다. 비어 있는 연결은 "자료 없음"으로 표기하고 추정해 채우지 않는다.

### 6-1. 최소 구현 기능

| 기능 | 데이터 사용법 |
|---|---|
| 검색 | 세 분류의 `levels.*`와 `jobs`를 명칭 부분일치로 훑는다. 결과에 분류 이름 배지를 붙인다 |
| 계층 트리 | `parent`로 자식 목록을 만들고, 펼침 상태만 유지한다. 1,096개 세분류를 한 번에 렌더하지 말고 레벨별 지연 렌더 |
| 역추적 | KSCO 세분류 → `keco_ksco` 역인덱스 → KECO 세분류 → `ncs_keco` 역인덱스 → NCS 소분류 → `ncs.units`(subs 포함) |
| 직업 카드 | `jobs`에서 `keco_code`/`ksco_code`로 세 분류 명칭을 조인해 한 줄씩 |
| 능력단위 | `units.filter(u => u.subs.includes(세분류코드))`, `level`·`hours` 표시, `sub_link==="code"`면 작은 표시 |

### 6-2. 성능

- 3.6MB JSON 한 번 로드 후 메모리 인덱스(코드→노드 Map, 부모→자식 Map, 역매핑 Map)를 만든다. 첫 화면에서 전체를 그리지 않는다.
- 검색은 디바운스 200ms, 결과 50건 단위 더 보기.

## 7. 갱신 절차 (피클 담당)

1. `data.go.kr`에서 위 6종 원자료를 인증키 없이 다시 내려받는다(파일데이터 상세의 「다운로드」와 같은 경로).
2. NCS 고시 별표(HWPX)와 KSCO 고시 항목표(HWPX)를 표 단위로 파싱한다(병합 셀은 첫 문단만 사용).
3. `taxonomy.json`을 다시 만들고 `python3 taxonomy/data/validate.py`로 **오류 0건**을 확인한다.
4. `meta.counts`·`meta.coverage`와 이 문서의 실측 건수가 달라지면 함께 고친다.
5. `main`에 올린 뒤 Pages에서 `HTTP 200`을 확인한다.

## 8. 알려진 한계 (화면에 숨기지 말 것)

1. NCS↔KECO는 **소분류 단위, 144/495 KECO**만 공식 매핑이 있다.
2. KECO 세분류 16개는 KSCO 연결이 없다. KONET 직업 393건은 KSCO가 `null`이다.
3. 능력단위 146건은 고시 별표에 없어 분류번호로 이었다(`sub_link: "code"`).
4. NCS `legacy` 17건은 현행 고시에 없는 코드다.
5. KSCO 명칭은 8차 고시 표기 그대로다(가운뎃점 `‧` 등). 검색할 때 `·`/`‧`/`ㆍ`를 같은 문자로 정규화하면 편하다.
6. KECO 2025는 2018년판과 **코드 번호가 달라졌다**. 2018년 자료와 코드로 섞지 말 것.
