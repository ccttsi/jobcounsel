## 무엇을 · 왜

무료 자원을 늘어놓기만 하고 **누가 무엇을 어디까지 맡는지**가 문서에 없었다. Make는 무료 한도가 **월 1,000 오퍼레이션**뿐인데, 스텝이 늘거나 루프를 돌면 수집이 멈추고, 새로 합류한 무료 팀원(Jina·Firecrawl·Groq·Kaggle 등)과 기존 팀원(클로드·피클·Actions·Supabase) 사이의 경계도 정해 두지 않았다. 태화님 지시(2026-11-22)로 **Make ↔ 무료 팀원 분업 지침을 저장소 원본에 명문화**하고, 클로드가 새 수집기를 설계할 때도 같은 규칙을 따르게 했다.

### 바뀐 파일

| 파일 | 무엇을 더했나 |
|---|---|
| `ops/ROLES.md` | 「Make ↔ 무료 팀원 분업」 절 신설 — ① 단계별 담당 표(감지→추출→초안→검수→배포→학습→앞단→보관) ② Make가 하지 않는 것 ③ 한도·비축 표(Jina 20 RPM · Firecrawl 월 1,000 중 200 비축·하루 25 · Groq 하루 1,000 · Kaggle 주 30시간 중 6 비축) ④ 신규 10팀 경계 ⑤ 기존 팀원(클로드·피클·Actions·Supabase·Notion·Playwright·Drive) 경계 ⑥ 연결은 GitHub 한 곳, 앞단만 Cloudflare 직통 + 키 보관. Make 행을 「정기 크롤링의 감지·전표 전담(1~2스텝)」으로, GitHub Actions 행을 새로 넣었다 |
| `ops/CONNECTORS.md` | 무료 팀원 10팀의 콘솔·주소·무료 한도·키를 두는 자리 표, 「비밀값을 두는 곳 — 세 자리뿐」 표(GitHub Secrets · Cloudflare Secrets · 로컬 `/workspace/.secrets/`) |
| `CLAUDE.md` | 클로드가 수집·가공·학습·배포를 설계할 때 Make에는 1~2스텝만 두고, 추출·초안·검증·학습·앞단을 맡길 곳을 정한 규칙 한 문단 |
| `ops/CI.md` | 무거운 검사·빌드는 GitHub Actions에서(공개 저장소 무제한) — Make에 싣지 않는다는 한 줄 |

### 지킨 선

- **사실·저작권(Track A/B) 검수는 무료 팀원에게 넘기지 않는다** — 클로드·피클·`collect_gate.py` 몫으로 적었다(헌법 제1·2조).
- **키 값은 어느 문서에도 쓰지 않았다.** 이름과 보관 위치만 적었다(헌법 3-2).
- 추출이 세 번 실패하면 그 항목은 **생략 + 출처 URL**로 처리한다(2-1)는 규칙을 분업 표에 붙였다.
