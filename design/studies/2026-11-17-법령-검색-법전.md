# 법령 찾아보기 — 검색 한 칸 + 한 줄 결과 + 세 칸 상세 — 2026-11-17

- (웹 밖) 종이 법전·조문집의 판형 — 목차에서 조문 번호로 바로 들어가고, 한 쪽에 한 조문, 쪽 번호가 항상 같은 자리에 있다. 이 **위치 감각**만 가져왔다.
- 국가법령정보센터 자치법규 화면(서울특별시 청년일자리 기본 조례)은 **원문 확인용**으로만 열었다. 배치·색은 참고하지 않았다.

## 추상화한 원리
1. **찾는 화면과 읽는 화면을 한 몸으로 두지 않는다** — 검색은 즉시(0.1초), 읽기는 조용히. 결과를 누르면 같은 자리에서 상세로 바뀌고 주소(`#law=…`)가 남는다.
2. **결과 한 줄에 «왜 걸렸는지»를 붙인다** — 상황 이름과 조문 번호를 결과 줄에 함께 보여 주면, 두 번째 결과를 열어 보는 왕복이 줄어든다.
3. **자료가 늘어도 틀이 무너지지 않게 «칸»을 나눈다** — 풀이·사례 / 시각자료 / 조문을 각각 독립 칸으로 두면, 시각자료가 없는 법령은 칸째 사라지고 빈 자리가 남지 않는다.
4. **법전의 위치 감각은 «쪽 번호»와 «목차»가 만든다** — 진행 띠·점이 아니라 `12 / 50` 숫자와 목차의 현재 절 표시.

## 자체 작성 패턴
- **법령 찾기 한 칸**(`law/index.html` `.qbar`) — 입력 즉시 rAF 한 번으로 결과 갱신, 결과 줄은 44px 이상의 한 줄 링크.
- **가변형 시각자료 슬롯**(`law/app.js` `visualHTML`) — `visual.kind`(bars·compare·flow·timeline)에 따라 인라인 SVG 없이 CSS 막대·격자로 그린다. 없으면 요소 자체를 만들지 않는다.
- **세 칸 상세**(`.dt-a` / `.dt-v` / `.dt-t`) — 휴대폰은 탭 2~3개, 큰 화면은 2단(풀이·사례 | 시각자료 위·조문 아래).
- **법전 리더**(`.bk`) — 목차(법령 → 조문) + 한 조문 한 쪽, `←/→`·PageUp/Down·Home/End·가로 끌기, 휴대폰 목차는 아래에서 올라오는 시트. 쪽 전환은 `transform`·`opacity`만, `jc-busy` 이벤트로 형광펜·포스트잇에 알린다.
- 접근성: 탭 `role=tablist`/`aria-selected`, 조문 칩 `aria-pressed`, 리더 `aria-live=polite`, 모든 누를 것 44px.

## 시안 비교
- **안 A — 검색 + 한 줄 결과 + 세 칸 상세(채택)**: 밀도 높음(첫 화면에서 8건이 보임), 직관성 좋음(한 칸→한 줄→세 칸), 확장성 좋음(법령이 2배가 되어도 결과 줄·칸 구조 그대로). 채택.
- **안 B — 분류 트리(법 → 장 → 조)를 왼쪽에 고정**: 위치 감각은 좋으나 첫 화면에서 「무엇을 찾아야 하나」를 사용자가 먼저 정해야 했다. 상담 장면에서는 상황 낱말로 들어오므로 탈락.
- **안 C — 카드 격자(법령마다 카드)**: 카드가 8건일 때는 보기 좋지만 100건이 되면 훑기·비교가 무너진다. 「법령은 비교 대상이 아니라 찾는 대상」이라 탈락.
