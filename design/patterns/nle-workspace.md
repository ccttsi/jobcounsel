# 패턴 — 편집대 작업공간 (nle-workspace)

적용: `/portfolio/`(포트폴리오 편집실)처럼 **여러 자료를 한 화면에서 골라 고치고, 시간·순서 위에 올려 놓는** 화면.
공통 원칙·토큰은 `../../DESIGN.md`, 손맛은 `touch-physics.md`를 함께 읽는다.
영상 편집 프로그램의 창 구성(소스 · 모니터 · 인스펙터 · 타임라인)은 업계 공통 관습이라 빌려 쓸 수 있지만, **특정 앱의 배치 비율·색·아이콘·모양 조합을 따라가면 안 된다**(DESIGN §0-1). 여기서는 "네 칸이 각각 무엇을 맡는가"만 가져왔다.

## 1. 네 칸의 역할

| 칸 | 맡는 일 | 하지 않는 일 |
|---|---|---|
| 소스(왼쪽) | 이 화면이 다룰 것의 목록(장면·소재·트랙·점검 항목) | 긴 설명·근거 |
| 모니터(가운데) | 지금 고른 것 하나를 크게, 결론부터 | 목록·필터 |
| 인스펙터(오른쪽) | 고른 것의 세부·기준·체크 | 새로 고르기 |
| 타임라인(아래) | 순서·시간·개수를 한 줄로 | 세부 문장 |

- 큰 화면(≥1200px): `grid-template-columns: 250px minmax(0,1fr) 300px; rows: minmax(0,1fr) 208px` + `grid-template-areas:"bin viewer insp" "tline tline tline"`.
- 작업대 높이를 `calc(100dvh - 머리높이)`로 고정하고 **각 칸이 안에서 스크롤**한다. 문서 전체가 늘어나지 않아 화면 분량이 1.0~1.1에 머문다(실측 1280·1600: 1.05~1.07).
- 칸마다 `overflow:auto; overscroll-behavior:contain`. 스크롤은 칸의 것이지 페이지의 것이 아니다.
- 600–1199px: `bin | viewer` 두 칸 + 아래 타임라인. 인스펙터는 아래에서 올라오는 시트로 뺀다.
- <600px: 세로 흐름. 소스는 **가로 릴**(`scroll-snap-type:x mandatory`), 모니터·타임라인은 한 단, 인스펙터는 시트.

## 2. 재생헤드(스크럽)

- 시간 위를 오가는 조작은 **`input[type=range]`**로 만든다. 키보드·스크린리더 의미가 그대로 남고, 끌기 코드를 따로 쓰지 않는다. 높이 44px, `touch-action:pan-y`.
- 재생헤드 선은 `div` 하나를 `transform:translateX(px)`로만 움직인다(위치 계산은 `clientWidth × t / total`).
- 채워짐은 트랙 배경의 `linear-gradient`와 `--v`(0~100%)로 그린다. 값이 바뀔 때 `--v`만 갱신하면 되고 레이아웃을 다시 재지 않는다.
- 값이 바뀌면 **모니터만 다시 그리고**, 타임라인은 다시 그리지 않는다. 다시 그리면 끌고 있던 `range` 노드가 사라져 끌기가 끊긴다.
- 같은 초가 여러 번 들어와도 같은 장면이면 다시 그리지 않는다(장면 인덱스 비교).
- **장면을 고르면 재생헤드는 그 클립의 정가운데에 둔다**(시간은 `(t0+t1)/2`, 예: 표지 4초). 구간 시작점에 두면 선이 칸 경계선에 걸쳐 어느 칸을 보는지 흐려진다. 끌기·키보드로 오갈 때는 시간을 그대로 따라간다.
- 재생헤드 좌표는 `t / total` 퍼센트가 아니라 **그 클립의 실제 좌표 사이 비율**로 잡는다. 클립은 좌우 여백·테두리가 flex 비례에 섞이지 않아 칸마다 고정 폭이 더해지므로, 퍼센트로만 놓으면 짧은 칸에서 최대 1~6px 어긋난다. 누른 자리를 시간으로 되돌릴 때도 같은 좌표표를 쓴다(눌린 자리와 재생헤드가 어긋나지 않게).

## 3. 클립

- 클립 폭은 **값에 비례**한다(`flex: {duration} 1 0`). 시간 길이가 곧 폭이면 눈이 순서와 길이를 따로 배우지 않아도 된다.
- **클립의 좌우 여백은 0으로 두고 글자만 안쪽으로 들인다**(`.sc{padding:6px 0}`, `.sc b/small{padding:0 9px}`). 클립 자체에 좌우 여백을 주면 그 폭이 비례 계산 밖에서 칸마다 더해져, 길이 비례도 재생헤드 정렬도 함께 틀어진다.
- 휴대폰에서도 비례를 지킨다. 46px 미만으로 좁아진 칸은 이름을 넣으면 말줄임만 남으므로 **번호(01~05)만** 남긴다(`.sc.tiny`). 비례를 포기하고 고정 폭으로 바꾸면 재생헤드가 가리키는 시간과 칸이 어긋난다.
- 클립 자체가 단추다(44px 이상). 상태는 색만 쓰지 않는다: 선택 `aria-current` + 1px 테두리, 올림/컷은 `↑`·`—` 글자와 배경, 통과/미확인은 `✓`·`!`.

## 4. 비교대 — 전후 대조

- **글에는 겹치는 커튼을 쓰지 않는다.** 두 문장을 같은 자리에 겹쳐 놓고 일부를 가리면, 가려진 쪽 글자가 반쯤 잘려 어느 쪽도 읽히지 않는다(첫 구현 실패).
- 대신 **두 칸을 나누는 경계 손잡이**를 쓴다: `grid-template-columns: var(--xpx) minmax(0,1fr)`, 손잡이는 `translateX(var(--xpx))`. 칸이 좁아지면 글자가 그 칸 안에서 다시 흐르므로 양쪽 다 끝까지 읽힌다.
- 경계는 20~80%로 제한한다(한 칸이 0이 되면 읽을 것이 없다).
- 손잡이는 `role="slider"` + `tabindex="0"`, 화살표 키로 5%씩. `aria-valuenow`에 현재 %.
- 600px 미만은 **위아래로 쌓고 손잡이를 숨긴다**. 좁은 두 칸은 글을 세로로 눌러 읽기 나빠진다.
- 전후 예시는 별도 팝업(`.cmpfs`, 종이 바탕)에 두고, 작업 화면에는 「전후 비교 열기」 한 줄만 남긴다. 편집 칸이 좁아 예시가 잘리는 일을 막는다.

## 5. 모드·단계 전환

- 단계(스캔 · 컷 · 조립 · 검문소)는 **세그먼트 전환기** 하나로만 바꾼다. 화면 길이를 늘이지 않고 가운데 칸만 갈아 끼운다.
- 단계마다 네 칸의 내용이 모두 바뀌지만 **틀은 그대로**다. 같은 자리에서 내용만 바뀌면 사용자는 새 화면을 배우지 않아도 된다.
- 다른 독자(상담사·강사)를 위한 화면은 **머리 스위치 한 번**으로 갈아 끼우고, 그 화면에서는 단계 전환기를 숨긴다(단계가 의미 없으므로).

## 6. 검수 (이 유형에서 반드시 재는 것)

- [ ] 6 해상도 × 밝게/어둡게에서 콘솔 오류 0 · 가로 넘침 0 · 44px 미달 0
- [ ] 화면 분량: 큰 화면 ≤1.5(실측 1.06), 휴대폰 ≤2.5(실측 1.52)
- [ ] 재생헤드를 끌어도 타임라인 노드가 사라지지 않는가(끌기 유지)
- [ ] 단계를 오가도 입력한 문장·고른 소재가 남는가
- [ ] 시트·팝업이 Esc·바깥 누름으로 닫히고, 닫힌 뒤 초점이 연 단추로 돌아가는가
- [ ] 좁은 화면에서 비교대가 위아래로 쌓이고 손잡이가 숨는가

## 7. 도태 (이 유형에서 다시 쓰지 않는 것)

- **글 위에 겹치는 전후 커튼**(clip-path로 절반 가리기) — 두 문장이 섞여 읽힌다. → 두 칸 경계 손잡이(§4).
- **재생헤드 값을 받을 때마다 타임라인 전체 다시 그리기** — 끌던 `range`가 사라진다. → 모니터만 다시 그리기(§2).
- **작업대에 고정 높이를 주지 않고 카드를 세로로 쌓기** — 휴대폰 3~4화면. → 네 칸 + 칸별 스크롤(§1).
- **비례 폭 클립을 좁은 화면에 그대로** — 84px 미만이 되어 짚을 수 없다. → 고정 폭 + 가로 스크롤(§3).
- **모든 내용을 양쪽에 다 두기** — 목록을 누르면 오른쪽에 같은 목록이 또 있었다. → 목록은 소스, 세부는 인스펙터(§1).
