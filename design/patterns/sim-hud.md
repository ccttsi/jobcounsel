# 패턴 — 계산기 · 시뮬레이터 · 실무 HUD (sim-hud)

적용: `/hud/`(국취 상담 HUD), `/vpi/`(직업선호도검사 L형 해석 시뮬레이터), `/dacum/`(DACUM 마스터), `/talk/`(상담 대화 연습장)의 입력·판정·결과 구역.
공통 원칙·토큰은 `../../DESIGN.md`, 손맛은 `touch-physics.md`를 함께 읽는다.

## 1. 입력과 결과의 자리

- **좌입력 · 우결과**를 큰 화면의 기본으로.(≥ 1024px) 입력이 길어 화면을 넘겨도 결과가 사라지지 않아야 한다.
- **결과는 따라온다.** 오른쪽 결과 칸은 `position:sticky; align-self:start`로 붙인다(국취 HUD 유형 판정, 1024px 이상). `top`은 붙어 있는 머리말 높이 + 여백(`116px` 기준).
- **휴대폰은 반대 순서.** 입력이 한 단으로 내려오고, 결과는 화면 아래 고정 띠 또는 「결과 보기」로 부른다. 결과를 위에 두면 스크롤을 올려야 해서 계산기를 못 쓴다.
- **제출 단추를 두지 않는다.** 입력이 바뀌는 즉시 다시 계산한다(같은 프레임에 한 번, `requestAnimationFrame` 묶음). 「계산」 단추는 결과가 언제 갱신되는지 모르게 만든다.
- **빈 상태를 설계한다.** 아무것도 고르지 않았을 때 결과 칸은 빈 상자가 아니라 「왼쪽에서 3개만 고르면 나옵니다」처럼 다음 행동을 말한다.

## 2. 판정·점수 표시

- 점수는 숫자 + 한 줄 근거. 큰 숫자만 두면 사용자는 왜 그 숫자인지 모른다(예: 유형 판정은 유형 이름 + 결정적 조건 2개).
- 비율·게이지는 `scaleX`. 값이 바뀔 때만 차오르고, 감속 모드에서는 즉시.
- 단계(스텝)가 있는 계산기는 현재 단계를 머리에 한 줄로 남긴다(`1 / 4`). 뒤로 가도 입력은 남는다.
- 결과가 조건에 따라 달라지면, **어떤 조건이 결과를 바꿨는지**를 결과 옆에 적는다(「직원 규모 조건으로 275곳 제외」처럼 데이터가 말해 주는 사실만).
- 결과는 화면 안에서 끝낸다. 복사·인쇄·파일 저장 단추는 두지 않는다(PR #49·#52, 사이트 밖으로 내보내는 기능 금지).

## 3. 조건 필터(HUD·찾기 공통)

- 필터는 칩으로. 고른 칩은 결과 수와 함께 위쪽에 모으고, 「조건 풀기」 한 번으로 전부 푼다.
- 필터 상태는 주소에 남긴다. 고를 때는 `replaceState`(뒤로 가기가 필터마다 쌓이지 않게), 상세로 들어갈 때만 기록을 남긴다.
- 조건이 서로 배타적이면(업종 대분류 ↔ 기업집단) 바꿀 때 이전 것을 자동으로 푼다. 둘 다 켜진 채 아무 결과 없는 상태를 만들지 않는다.
- 없는 조합은 결과 0을 보여 주되, 어느 조건을 풀면 나오는지 한 줄로 알려 준다.

## 4. 훈련·연습 화면(대화 연습장 유형)

- 장면·역할 고르기는 카드 한 장씩. 고른 상태는 테두리 + 배경 두 신호로(색만으로 구분하지 않는다).
- 대화 기록은 최신이 아래, 자동 스크롤은 사용자가 위로 올려 읽는 중이면 멈춘다.
- 입력창은 화면 아래 고정, `env(safe-area-inset-bottom)` 존중. 키보드가 올라오면 입력창이 가려지지 않아야 한다(`visualViewport` 또는 `100dvh`).
- 피드백(교정·힌트)은 접어 두고 「교정 보기」로. 답을 먼저 노출하면 연습이 되지 않는다.

## 5. 건너뛴 자리·진행 표시

- 아직 채우지 않은 칸은 자리 표시를 남긴다. 그림자 보간 대신 `steps(1)`로 테두리를 1.5초 켰다 끈다(DACUM).
- 남은 단계가 많으면 목록을 접고 「3단계 남음」만. 단계 이름을 전부 늘어놓으면 화면이 체크리스트가 된다.

## 6. 검수 (이 유형에서 반드시 재는 것)

- [ ] 1024·1180·1280에서 결과 칸이 스크롤 중에도 보이는가(sticky 동작, 가림 없음)
- [ ] 390·360에서 입력 → 결과 도달까지 스크롤 거리와 결과 띠 가림
- [ ] 연속 입력 시 반응 지연: 키 입력 → 결과 갱신까지 p95 ≤ 50ms, 100ms 넘는 끊김 0회
- [ ] 조건 왕복(걸기·풀기·뒤로 가기)에서 상태와 주소가 어긋나지 않는가
- [ ] 빈 상태·결과 0 상태에 다음 행동이 적혀 있는가
- [ ] 콘솔 오류 0, 가로 넘침 0

## 7. 도태 (이 유형에서 다시 쓰지 않는 것)

- **「계산」 단추를 눌러야 결과가 바뀌는 계산기** — 입력과 결과의 관계가 끊긴다.
- **휴대폰에서 결과를 입력 위에 두기** — 스크롤을 올려야 해서 못 쓴다.
- **점수만 크게 보여 주고 근거를 접기** — 판단을 대신하지 못한다.
- **`box-shadow` 보간으로 단계 표시 깜박이기** — 그림자 대신 `steps(1)` 테두리.

## 8. 먼저 찍고 맞대기 (추정 → 실제 비교) — 2026-11-16 `/reality/`

통계를 보여 주기 전에 사용자의 짐작을 먼저 받는다. 짐작과 실제의 차이가 곧 메시지다. (학습 노트 `design/studies/2026-11-16-estimate-then-compare.md`)

- **입력은 기본 `input[type=range]`.** 키보드·스크린리더 의미가 그대로 남는다. 겉모양만 바꾸고(`appearance:none` + 트랙·손잡이 의사 요소), 높이 44px, `aria-valuetext`에 단위를 붙인 값(「45%」). 가로 끌기라 `touch-action:pan-y`.
- **눈금자 위 두 표지.** 「내 예측」(벽돌색 ▼)과 「실제」(강조색 ●)를 모양까지 다르게 둔다(색만으로 구분하지 않는다). 위치는 전체 폭 상자에 `transform:translateX(p%)` — 상자가 트랙과 같은 폭이라 p%가 곧 눈금이다. 레이아웃 속성을 건드리지 않는다.
- **「실제 값 보기」 단추는 예외적으로 둔다.** 계산 단추가 아니라 공개 단추다. 바로 보여 주면 짐작을 받을 수 없다. 공개 뒤에는 슬라이더를 움직이면 차이 문장이 즉시 다시 계산된다(§1 원칙 유지).
- **공개 모션은 하나.** 실제 표지가 내 예측 자리에서 실제 자리로 미끄러진다(`transform` 0.5s). 감속 모드·집중 보기에서는 즉시.
- **비율은 100점 빈도 그림.** 두 칸으로 나뉘는 비율(합 100)은 점 100개(20×5)로 「100명 중 17명」처럼 분모를 보여 준다. 세 칸 이상은 막대(`scaleX`), 비교군은 막대 + 전체 값 세로선.
- **모든 통계 카드 끝에 출처 한 줄**: 증거 수준 꼬리표(공식 / 민간·모형은 노란색) · 기관 · 조사명 · 기준시점 · 원문 링크.
- **나쁜 소식은 지우지 않는다.** 반박 화면에서도 불리한 사실(임금 격차 등)은 노란 칸에 「지우지 않고 그대로 두는 사실」로 남긴다.
- **통제할 수 있는 행동은 하나만 고르게 한다**(라디오). 여러 개를 한꺼번에 잡게 하면 부담이 된다(데이터셋 설계 의도).
- **키 큰 조건 칸에는 `sticky`를 걸지 않는다.** 화면보다 긴 필터 칸을 붙이면 아래 칩에 닿을 수 없다. 결과 칸처럼 짧은 것만 붙인다.
- 실측(헤드리스 크롬, 390×844·1280×800): 슬라이더 연속 입력 20회 p95 10.3ms·long task 0 / 공개 전환 프레임 p95 16.7ms·최대 20.4ms / 단계 전환 최대 50.1ms(한 번 그리는 순간) / 대기 rAF 0 / 감속 모드 실행 중 애니메이션 0.

## 2026-11-16 턴 타이머 — 잉크 악보선 (`/interview/`)
- 시간 감소는 CSS 애니메이션 한 개(scaleX, duration = 제한 시간), 숫자는 실행 중에만 250ms 간격 확인. 상시 rAF 없음.
- 화면을 다시 그려도 타이머가 이어지게 `animation-delay: -경과초`로 같은 지점에서 다시 붙인다. 멈춤은 `animation-play-state`.
- 구간 눈금(도입·사례·연결)과 「지금 · 도입」 낱말이 압박보다 리듬을 알려 준다. 초과는 실패가 아니라 기록.

## 2026-11-19 펼침이 읽던 글을 밀지 않게 — 판(dock, `/interview/` 답변 시간)
태화님 지적: 「방어 누를 시 답변시간이 펼쳐지는 건 좋으나 방어 부분이 밑으로 밀려나가서 읽는데 방해됨」. **패널을 카드 안(글 흐름)에 넣으면 펼칠 때마다 읽던 본문이 아래로 밀린다.**

- **판은 정상 흐름 밖에 둔다.** 큰 화면은 턴 상자(`.pane` flex)의 마지막 자식(`flex:none`)으로 넣어 스크롤 영역만 줄인다 — 안쪽 내용의 좌표는 그대로다. 휴대폰은 `position:fixed` 바닥 판.
- **밀리지 않는 근거는 좌표다.** 페이지 스크롤·상자 스크롤을 건드리지 않으므로, 판이 열려도 읽던 카드의 `getBoundingClientRect().top` 이동은 `0.00px`. 스크롤 보정(scrollBy)으로 맞추는 방식은 스크롤 끝·브라우저 스크롤 앵커링과 겹쳐 어긋나므로 쓰지 않는다.
- **바닥 고정 도구와 겹치지 않게 비켜 준다.** 판이 오른쪽 아래 도구 띠에 닿을 때만 `--lift`(형광펜)·`--jca-lift`(비서)를 판의 위쪽 끝까지 올린다. 형광펜은 스스로 다시 앉는 코드가 있어 페이지 쪽에서 CSS 변수 규칙(`body.tdock-on #jc-marker-ui{--lift:…!important}`)으로 고정한다(인라인 style은 나중에 지워지지만 CSS 규칙은 남는다). 판이 아래 도구 띠에 닿지 않으면(집중 보기에서 판이 떠 있을 때) 올리지 않는다.
- **모션 중 측정 주의.** 판이 `translateY`로 떠오르는 동안 `getBoundingClientRect`를 재면 14px 어긋난다. 바닥 고정 판은 `offsetHeight`로 위쪽 끝을 구한다.
- 휴대폰은 판 높이만큼 `.wrap` 아래 여백을 더해(열려 있을 때만) 마지막 글이 판 위로 올라와 읽힌다. 여백은 아래에 붙으므로 위 내용은 움직이지 않는다.
- 실측(390×844·1280×800 × 밝게·어둡게 × 일반·집중 보기 + 360×640·820×1180·768×1024·900×700·899×800·1600×900·844×390): 방어 본문 시작 Y 이동 **0.00px**, 가로 넘침 0, 콘솔·페이지 오류 0, 판 높이 149px(휴대폰)·155px(큰 화면), 길이 단추 줄 넘침 0.

## 2026-11-20 규모 전환 시뮬레이터 (`/fin-lab/`) — 같은 숫자를 네 규모로 다시 읽기

- **규모 전환은 숫자가 아니라 기준선을 바꾼다.** 입력값은 그대로 두고 규모별 점수 구간(`bands: [값, 점수]`)만 갈아 끼우면, 같은 부채비율 220%가 대기업 33점·스타트업 85점이 된다. "같은 숫자, 다른 판정"이 슬라이더를 만지지 않고도 증명된다 — 화면을 스위치 하나로 가르는 대신 **해석의 기준을 스위치로 가른다**.
- **판정 카드에 비교 한 줄을 붙인다.** `같은 숫자를 ○○ 기준으로 보면 "△△"(57점)입니다.` 규모 차이를 사용자가 스스로 찾게 두지 않고, 가장 차이가 큰 다른 규모를 골라 한 줄로 대신 말해 준다.
- **오각형 꼭짓점 ↔ 슬라이더는 역함수로 잇는다.** 끌기는 축 점수(0~100)를 만들고, 그 점수를 각 비율로 **역산**(`invInterp`)해 값을 채운다. 슬라이더는 값→점수 정방향이라, 두 입력이 같은 상태 하나를 공유해 서로 덮어쓰지 않는다. 키보드는 방향키 3점·Page 10점·Home/End.
- **막대는 절대값 정규화보다 "읽히는 최소 높이"가 먼저다.** 150억 기준으로 나누면 30억 출금이 12px로 보여 작은 일처럼 읽혔다. 60억 기준 + 최소 18%로 바꿔 방향(부호)과 크기가 함께 보이게 했다.
- **워터폴은 값보다 계단이 먼저다.** 막대 안 숫자는 큰 칸에 눌려 겹치므로 라벨 줄로 내리고(`매출 100 / 변동비 −62`), 단계 사이에 1px 연결선을 그어 한 줄로 읽히게 한다. 눈금(lo/hi)이 바뀌면 전체 높이가 다시 계산되는 것이 정상이다.
- **집중 보기에서 도구가 사라지지 않게.** 공용 `prefs.js`는 `<main>` 밖 형제를 숨기므로 탭·프리셋·규모 전환기가 함께 사라진다. `window.JC_IMMERSIVE={keep:'.strip, .toast'}`로 스트립을 남기고, 머리말에만 있던 규모 전환기는 `html[data-jc-imm]`에서만 보이는 한 벌(`.imm-scale`)을 스트립에 두어 중복 없이 되살린다(두 벌의 `aria-pressed`는 같은 상태에서 함께 갱신).
- **연습용 값에는 출처의 층을 밝힌다.** 관행 기준선(200%·100%·1배·3년)과 이 자료실이 정한 축 구간(60·75점)을 바닥에서 분리해 적고, 실존 기업 수치를 만들지 않는다는 문장을 첫 줄에 둔다.
- **금액으로 말하는 탭은 '무엇이 입력이고 무엇이 계산인지'를 화면에 적는다.** 재무제표 3표는 비율만으로는 말할 수 없어 크기(매출 규모·자산배수)를 슬라이더로 드러내고, 과거 해는 지금 값에서 기울기만큼 되돌려 만든다는 규칙을 카드 아래 한 줄로 밝혔다. 지어낸 기업·통계를 붙이지 않으면서 금액을 말하는 방법이다.
- **표는 서로 맞물려야 한다(tie).** 부채비율은 부채÷자본, 부채 잔액은 재무활동 현금흐름만큼 되돌리고, 현금은 기말에서 기초로 굴린다. 한 줄이라도 다른 정의를 쓰면 같은 화면의 두 탭이 다른 회사가 된다 — 기본값(판관비율·이자비용)도 1번 탭의 비율과 맞춰 두었다.
- **여러 해를 나란히 놓을 때는 '해의 열'을 공통 격자로.** 4열(항목·Y-2·Y-1·Y0) 격자를 세 표가 같은 값으로 쓰고, 합계 행만 위 테두리로 굵게. Y0 열만 진하게 두어 "지금"이 어디인지 좌표를 준다.
- **추이 막대는 해마다 다른 눈금을 쓰지 않는다 — 지표마다 세 해 범위 안에서만 잰다.** 값은 막대 위가 아니라 이름 칸(Y0 값 + 전년 증감)에 적는다. 막대 위 숫자는 가장 큰 막대에서 그림 밖으로 나가고, 작은 막대에서는 읽히지 않는다.
- **좁은 화면에서는 표·판독을 남기고 도구를 접는다.** 3표 탭은 760px 미만에서 추이 카드, 1100px 미만에서 조정 카드를 `<details>`로 접었다(요약에서 설명 문구는 숨긴다 — 두 줄로 깨진다). 첫 화면의 목적이 '세 표가 한눈에'이기 때문이다.

### 2026-11-20 (3차) 이지·심화 두 벌과 깨진 축 — 비전공자 접근성 (`/fin-lab/`)

- **부호 막대는 기준선에 `bottom`/`top`으로 붙인다.** 위아래로 갈리는 막대에 `top:50%` + `transform-origin:top`을 쓰면 `scaleY`가 **아래로** 자라 양수와 음수가 뒤집힌다(실기기에서 +122·+128·+40이 전부 아래로 그려진 원인). 양수는 `bottom:50%`·`transform-origin:bottom`, 음수만 `top:calc(50%+4px)`·`transform-origin:top`. 검수는 `getBoundingClientRect()`의 막대 중심이 트랙 중심보다 위인지로 잰다(부호를 눌러 뒤집은 상태도 함께).
- **큰 값과 작은 값을 한 축에 담아야 하면 축을 한 번 꺾는다(브로큰 스케일).** 매출 100과 순이익 0.3을 0~100 선형 축에 두면 작은 칸은 2px로 깔린다. 값→높이 함수를 구간별 선형으로 두고(`v≤zp`는 아래 58%, 그 위는 위 42%) 이익 구간을 13~14배 늘리면 워터폴의 계단이 유지된 채 작은 칸이 20~45px로 읽힌다. 늘린 배율은 화면에 숫자로 밝히고(「14배 확대한 구간」) 옅은 띠·점선으로 경계를 표시한다. 최소 표시 높이는 2%, 0인 칸은 2px 선으로 남긴다(0을 '없음'으로 보이게 하지 않는다).
- **규모 전환은 판정만이 아니라 구조까지 바꾼다.** 손익(변동비·고정비·이자·세금)을 규모별 전형값으로 두면 같은 100에서 대기업은 변동비 62·순이익 1.9, 스타트업은 고정비 49·순이익 4.1, 공기업은 이자가 이익을 다 먹어 순이익 0.3이 된다 — 캔들이 눈에 띄게 달라진다. 대신 **한 곳에서만** 값을 만들고(`plCalc`) 1번 탭의 영업이익률·이자보상배율을 거기서 동기화한다. 두 탭이 다른 숫자를 말하면 그 화면은 다른 회사다.
- **이지/심화는 화면을 두 벌 만들지 않는다.** 같은 DOM에 `html[data-view]` 하나를 걸고 `.deepOnly`(심화 전용)·`.numCard`(표·숫자 덩어리)·`.easyOnly`(이지 전용) 세 클래스로 접는다. 표·차트 계산이 한 번만 돌고, 상태(규모·프리셋·슬라이더)가 전환에서 그대로 이어진다. 「숫자 줄이기」는 `.numCard`만 끄는 별도 축(`data-nums`)으로 두어 심화 안에서도 숫자를 덜 보게 한다.
- **이지 요약은 그 순간의 계산에서 문장을 만든다.** 세 줄(버는 힘·빚 부담·현금 안전)+한 줄 판정. 신호등은 색만 쓰지 않고 **문자(괜찮음/주의/위험)+모양(●▲✕)** 을 함께 준다. 비유는 한 문장 안에 넣고(「매출 100원 중 4원이 남습니다」) 숫자는 굵게 하나씩만.
- **용어 주석은 44px 규칙과 시각 크기를 동시에 만족시킨다.** `?` 단추를 44×44 투명 상자로 두고 20px 원은 `::before`로 그린 뒤 음수 여백으로 줄 높이를 되돌린다. 글자를 `::before`로 옮기면 대비 측정에서 빠지므로 색은 `--acc`(테마 대비 9:1)로 고정한다.
- **튜토리얼은 4단계 시트** — 제목·한 줄·3항목(왼쪽 이름표)·맺음말. 이전/다음은 `flex:1`로 같은 폭(249×44), 닫기 44px, 점(`i`)은 7px·현재만 알약. ESC·바깥 누름으로 닫고, 닫으면 연 단추로 초점을 돌려준다. 모달은 `backdrop-filter` 대신 46% 잉크 베일(§2-5).
- **접힌 카드의 머리도 카드 규격을 따른다.** `<details>` 요약에서 좌우 여백을 0으로 지우면 글자가 테두리에 붙어 다른 벤토 카드와 어긋나 보인다(실기기 지적). 요약은 `padding:5px 12px`, 「열기/닫기」는 테두리 알약으로 두어 카드와 같은 호흡을 준다.
