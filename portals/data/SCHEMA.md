# SCHEMA.md — 19번 채용공고 사이트 총망라 디렉토리 데이터 계약

이 문서는 `portals/data/portals.json`을 화면(`/portals/`)으로 구현하는 클로드 코드가 읽는 **계약서**다.
데이터는 피클(수집·검증)이 만들고, 화면 코드는 클로드가 쓴다(`ops/ROLES.md`).

- 파일: `portals/data/portals.json` (UTF-8, JSON, 약 50KB)
- 배포 주소: `https://ccttsi.github.io/jobcounsel/portals/data/portals.json`
- 스키마 버전: `meta.version = "1.0.0"` (2026-11-16)
- 검증: `python3 portals/data/validate.py` → **오류 0건** 통과본만 배포한다.
- 실측: **63곳** · 공공 6 / 민간종합·대기업 15 / IT·테크 12 / 경력·헤드헌팅 5 / 산업별 8 / 대상·근무형태 17

---

## 0. 이 데이터로 무엇을 하는가

구직자·상담사가 **"내 조건에 맞는 채용 사이트가 어디인가"**를 한 화면에서 찾도록 만든 디렉토리다.
공고를 모아 오는 것이 아니라 **사이트로 보내는 안내판**이다. 그래서 각 항목은 (1) 무엇에 특화됐고 (2) 누구를 위한 곳이며 (3) 상담에서 어떻게 쓰는지가 핵심이다.

> 학습·실습용 참고 자료다. 각 사이트의 공고 내용·채용 조건은 수시로 바뀌므로, 화면은 "이 사이트로 가서 최신 공고를 확인하라"는 안내로 끝나야 한다.

## 1. 최상위 구조

```json
{
  "meta":       { "dataset", "version", "sector", "built_at", "repository", "notice",
                  "counts", "verification", "license" },
  "sectors":    [ { "code", "name", "desc" } ],
  "vocabulary": { "roles": [], "eligibility": [] },
  "portals":    [ { "id", "name", "url", "sector", "operator", "roles", "eligibility",
                    "strengths", "tips", "verified_at", "http_status", "final_url", "verify_method" } ]
}
```

## 2. 레코드 필드

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ✔ | 소문자·숫자·밑줄. 화면 해시(`#portals/work24`)와 필터 키로 쓴다. **바꾸지 않는다** |
| `name` | string | ✔ | 사이트의 공식 이름. 로고·슬로건이 아니라 이름만 |
| `url` | string | ✔ | 검증된 **HTTPS** 주소. 화면은 이 주소로 새 탭 이동만 한다 |
| `sector` | string | ✔ | 아래 6개 대분류 코드 중 하나 |
| `operator` | string | ✔ | 운영 주체(기관·회사). 상담에서 신뢰도 판단 근거로 쓴다 |
| `roles` | string[] | ✔ | 특화 직무·직업. `vocabulary.roles` 값만 |
| `eligibility` | string[] | ✔ | 자격조건·대상. `vocabulary.eligibility` 값만 |
| `strengths` | string | ✔ | 이 사이트만의 강점 1~2문장(25~130자). **자료실이 직접 쓴 문장** |
| `tips` | string | ✔ | 상담사·구직자 활용 팁 1~2문장(20~170자) |
| `verified_at` | string | ✔ | 실제 접속 검증일 `YYYY-MM-DD`. 1.0.0은 전부 `2026-11-16` |
| `http_status` | number | ✔ | 검증 시 최종 응답. 1.0.0은 전부 `200` |
| `final_url` | string | ✔ | 리다이렉트를 따라간 뒤의 최종 주소(검증 증빙) |
| `verify_method` | string | ✔ | `curl` · `curl-mobile`(모바일 UA 필요) · `browser`(자동 접속 차단을 실제 브라우저로 확인) |

- 목록에는 없는 키를 만들지 않는다. 사이트의 공고·채용 건수·평점 같은 **변하는 값은 데이터에 넣지 않는다**(화면에서도 만들지 않는다).
- `strengths`·`tips`에 HTML 태그나 URL을 넣지 않는다(`validate.py`가 막는다).

## 4. 어휘 (`vocabulary`)

### 4-1. `roles` — 특화 직무·직업 (24개)

```
전 직종 · 사무·경영 · 영업·판매 · 생산·기술 · 연구·기술 · 연구·교육 · IT·개발 · 디자인 ·
기획·마케팅 · 미디어·방송 · 게임 · 유통·매장 · 의료·보건 · 간호 · 건설·건축 · 항공·운송 ·
물류 · 서비스 · 공공·행정 · 전문직 · 교육 · 현장실습 · 해외취업 · 프로젝트
```

- `전 직종`은 "직무를 가리지 않는 종합 사이트"라는 뜻이다. 다른 값과 함께 쓰지 않는다.
- `프로젝트`는 프리랜서·외주 단위 일감을 뜻한다(`프리랜서` 자격과 짝을 이룬다).

### 4-2. `eligibility` — 자격조건·대상·근무형태 (25개)

```
신입 · 경력 · 무관 · 청년 · 중장년 · 노인 · 장애인 · 경력단절여성 · 여성 · 외국인 ·
다문화가족 · 북한이탈주민 · 직업계고 · 대학생 · 석·박사 · 자격증 · 면허 · 해외취업 ·
프리랜서 · 단기·아르바이트 · 인턴 · 계약직 · 파견 · 임원 · 외국계
```

- 연령·대상 값(`청년`·`중장년`·`노인`)은 **그 사이트가 대상 사업을 운영한다**는 뜻이지, 다른 연령이 지원할 수 없다는 뜻이 아니다. 화면 문구도 그렇게 쓴다.
- `무관`은 경력 구분을 가리지 않는다는 뜻이다.
- 자격·면허가 필수인 곳(메디컬잡 등)은 `자격증`·`면허`를 함께 둔다.

## 5. 검증 정책 (데이터를 고칠 때 지킬 것)

1. **모든 `url`은 실제 접속으로 최종 200을 확인한 뒤 넣는다.** 3xx는 리다이렉트를 따라간 최종 응답이 200이어야 한다.
2. 자동 접속을 막는 사이트(403)는 **실제 브라우저로 화면이 뜨는지** 확인하고 `verify_method: "browser"`로 남긴다. 브라우저에서도 막히면 넣지 않는다.
3. 접속되지 않는 곳(시간 초과·TLS 오류·도메인 판매·폐쇄)은 **`meta.verification.excluded`에 이름·주소·사유를 남기고 목록에서 뺀다.** 조용히 지우지 않는다.
4. 이름이 비슷한 유인 사이트(도메인 판매 페이지, 다른 회사)를 실제 사이트로 착각하지 않는다. 응답 본문의 제목으로 확인한다.
5. `verified_at`은 **전수 재검증을 마친 날**로 통일한다. 일부만 확인하고 날짜만 올리지 않는다.

### 1.0.0에서 제외한 곳 (13)

클린아이 잡플러스(응답 없음) · 메디잡 www.medijob.co.kr(접속 불가) · 널스잡(응답 없음) · 호텔잡(.co.kr, 도메인 판매 페이지) · 에듀잡(TLS 오류) · 티처잡 · 쿡잡 · 투어잡(응답 없음) · 블라인드 하이어(TLS 인증서 오류) · 로버트월터스 코리아(403) · 우아한형제들 채용(403) · 유니코써치 루트(안내 페이지 → `/kr`로 대체) · 클린아이 계열(응답 없음)

## 6. 화면이 지킬 제약

- **공고 본문·로고·슬로건을 옮기지 않는다.** 화면에 보이는 설명은 이 JSON의 `strengths`·`tips` 문장뿐이다. 사이트 화면을 캡처해 붙이지 않는다.
- **내보내기 금지** — 저장·인쇄·PDF·복사 버튼을 만들지 않는다.
- 외부 링크는 `target="_blank" rel="noopener noreferrer"`로 새 탭에서 연다.
- 데이터에 없는 값(공고 수, 평점, 채용 중 여부)을 화면에서 만들지 않는다.
- 상세에는 `operator`·`verified_at`(검증일)·`roles`·`eligibility`를 그대로 노출해, "언제 확인한 정보인지"를 사용자가 알 수 있게 한다.
- 6개 대분류 + `roles` + `eligibility`의 **교차 필터**가 이 데이터의 핵심 용도다. 필터는 주소(hash)에 남겨 새로고침·공유에 견디게 한다.

## 7. 조인·확장 여지

- 14번 자격증 도감(`cert/`)의 자격명 → `roles`·`eligibility`(자격증) 태그로 연결하면 "자격 → 그 자격을 요구하는 채용 사이트"가 이어진다.
- 18번 분류 사전(`taxonomy/`)의 KECO 세분류 → `roles` 문자열 매핑은 **공식 매핑이 아니므로** 화면에서 "참고 연결"로 표시해야 한다(추정 금지).
- 19-1 후보: 사이트별 **모바일 앱 유무·회원가입 필요 여부·이력서 양식** 같은 실무 항목. 1.0.0에는 넣지 않았다.
