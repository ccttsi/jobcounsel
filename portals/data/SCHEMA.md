# SCHEMA.md — 고용 사이트 안내판(옛 채용 사이트 안내판) 데이터 계약

이 문서는 `portals/data/portals.json`을 화면(`/portals/`)으로 구현하는 클로드 코드가 읽는 **계약서**다.
데이터는 피클(수집·검증)이 만들고, 화면 코드는 클로드가 쓴다(`ops/ROLES.md`).

- 파일: `portals/data/portals.json` (UTF-8, JSON, 약 157KB)
- 배포 주소: `https://witw.pages.dev/portals/data/portals.json`
- 스키마 버전: `meta.version = "1.5.0"` (2026-11-27, 12개 시·도 지역 일자리 창구 추가 — 필드 변경 없음) · 마지막 전수 재확인 2026-11-23 · 2026-11-24·11-26 제외분 · 2026-11-27 시·도 포털 재확인
- 검증: `python3 portals/data/validate.py` → **오류 0건** 통과본만 배포한다.
- 실측: **136곳** · 공공 21 / 공시·기업정보 15 / 민간종합·대기업 17 / IT·테크 12 / 경력·헤드헌팅 5 / 산업별 9 / 대상·근무형태 19 / 직업훈련·자격·평생학습 16 / 고용·노동 행정·지원 15 / 직업·진로 정보·통계 7
- 운영 주체: **정부·공공기관 78 / 기업·그룹·단체 19 / 민간 포털·서비스 39**

## 0. 이 데이터로 무엇을 하는가

구직자·상담사가 **"내 조건에 맞는 채용 사이트가 어디인가"**를 한 화면에서 찾도록 만든 디렉토리다.
공고를 모아 오는 것이 아니라 **사이트로 보내는 안내판**이다. 그래서 각 항목은 (1) 무엇에 특화됐고 (2) 누구를 위한 곳이며 (3) **가서 무엇을 볼 수 있는지**, (4) 상담에서 어떻게 쓰는지가 핵심이다.

> 학습·실습용 참고 자료다. 각 사이트의 공고 내용·채용 조건은 수시로 바뀌므로, 화면은 "이 사이트로 가서 최신 공고를 확인하라"는 안내로 끝나야 한다.

**공시·기업정보 사이트도 같은 원칙이다.** 우리가 공시 자료나 기업 정보를 복제·수집해 싣지 않고, 공식 원문 페이지로 보내는 링크와 「가서 볼 수 있는 것」 요약만 둔다. 자동 수집·재배포를 막는 약관이 있거나 크롤링 분쟁이 있는 민간 데이터베이스는 넣지 않는다.

## 1. 최상위 구조

```json
{
  "meta":       { "dataset", "version", "sector", "built_at", "repository", "notice",
                  "counts", "verification", "license" },
  "sectors":    [ { "code", "name", "desc" } ],
  "vocabulary": { "roles": [], "eligibility": [] },
  "goals":      [ { "code", "name", "desc", "kids": [ { "code", "name", "desc" } ] } ],
  "portals":    [ { "id", "name", "url", "sector", "operator", "roles", "eligibility",
                    "strengths", "shows", "tips", "aliases?", "needs", "owner",
                    "verified_at", "http_status", "final_url", "verify_method", "verify_note?" } ]
}
```

## 2. 레코드 필드

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `id` | string | ✔ | 소문자·숫자·밑줄. 화면 해시(`#p=work24`)와 필터 키로 쓴다. **바꾸지 않는다** |
| `name` | string | ✔ | 사이트의 공식 이름. 로고·슬로건이 아니라 이름만 |
| `url` | string | ✔ | 검증된 **HTTPS** 주소. 화면은 이 주소로 새 탭 이동만 한다 |
| `sector` | string | ✔ | 아래 10개 대분류 코드 중 하나 |
| `operator` | string | ✔ | 운영 주체(기관·회사). 상담에서 신뢰도 판단 근거로 쓴다 |
| `roles` | string[] | ✔ | 특화 직무·직업. `vocabulary.roles` 값만 |
| `eligibility` | string[] | ✔ | 자격조건·대상. `vocabulary.eligibility` 값만 |
| `strengths` | string | ✔ | 이 사이트만의 강점 1~2문장(25~130자). **자료실이 직접 쓴 문장** |
| `shows` | string[] | ✔ | **가서 볼 수 있는 것** 2~4개(각 2~24자). 예: `사업보고서·분기보고서`, `등록 단체 현황`. 카드에는 앞의 몇 개와 `+n`, 상세에는 전부 보인다 |
| `tips` | string | ✔ | 상담사·구직자 활용 팁 1~2문장(20~170자) |
| `needs` | string[] | ✔ | **내담자 상황·목표** 코드 1~4개(4-3의 하위 코드). 첫 값이 그 사이트의 **대표 목적**이며, 화면은 「상황·목표」로 묶을 때 대표 목적 한 묶음에만 놓는다 |
| `owner` | string | ✔ | 운영 주체 갈래 `gov`(정부·공공기관) · `corp`(기업·그룹·단체) · `biz`(민간 포털·서비스) |
| `aliases` | string[] | – | **검색용 별칭**. 영문 약어·도메인·통칭·동의어(`gosi.kr`, `공거위`, `프랜차이즈`). 화면에 설명으로 쓰지 않고 검색에만 쓴다. 도메인은 `url`에서 자동으로도 색인된다 |
| `verified_at` | string | ✔ | 실제 접속 검증일 `YYYY-MM-DD`. 항목마다 그날 확인한 날짜를 적는다 |
| `http_status` | number \| null | ✔ | 검증 시 최종 응답. `verify_method: "official"`이면 `null` |
| `final_url` | string | ✔ | 리다이렉트를 따라간 뒤의 최종 주소(검증 증빙) |
| `verify_method` | string | ✔ | `curl` · `curl-mobile`(모바일 UA 필요) · `browser`(자동 접속 차단을 실제 브라우저로 확인) · `official`(공식 안내·공표로 확인 — 아래 5-3) |
| `verify_note` | string | 조건부 | `verify_method: "official"`일 때 필수. 무엇을 근거로 확인했고 왜 직접 응답을 못 봤는지 |

- 목록에는 없는 키를 만들지 않는다. 사이트의 공고·채용 건수·평점 같은 **변하는 값은 데이터에 넣지 않는다**(화면에서도 만들지 않는다).
- `strengths`·`tips`·`shows`에 HTML 태그나 URL을 넣지 않는다(`validate.py`가 막는다).
- `shows`는 **그 사이트에 들어가면 실제로 볼 수 있는 항목**만 적는다. 확인하지 않은 메뉴를 추측해 넣지 않는다.

## 4. 어휘 (`vocabulary`)

### 4-1. `roles` — 특화 직무·직업 (26개)

```
전 직종 · 사무·경영 · 영업·판매 · 생산·기술 · 연구·기술 · 연구·교육 · IT·개발 · 디자인 ·
기획·마케팅 · 미디어·방송 · 게임 · 유통·매장 · 의료·보건 · 간호 · 건설·건축 · 항공·운송 ·
물류 · 서비스 · 공공·행정 · 전문직 · 교육 · 현장실습 · 해외취업 · 프로젝트 ·
공무원·공직 · 공기업·공공기관
```

- `전 직종`은 "직무를 가리지 않는 종합 사이트"라는 뜻이다. 다른 값과 함께 쓰지 않는다.
- `프로젝트`는 프리랜서·외주 단위 일감을 뜻한다(`프리랜서` 자격과 짝을 이룬다).
- `공무원·공직`은 국가·지방공무원 임용시험 창구, `공기업·공공기관`은 공공기관·지방공기업 채용·경영공시 창구에 쓴다. 일반 종합 구인 사이트에는 붙이지 않는다.

### 4-2. `eligibility` — 자격조건·대상·근무형태 (25개)

```
신입 · 경력 · 무관 · 청년 · 중장년 · 노인 · 장애인 · 경력단절여성 · 여성 · 외국인 ·
다문화가족 · 북한이탈주민 · 직업계고 · 대학생 · 석·박사 · 자격증 · 면허 · 해외취업 ·
프리랜서 · 단기·아르바이트 · 인턴 · 계약직 · 파견 · 임원 · 외국계
```

- 연령·대상 값(`청년`·`중장년`·`노인`)은 **그 사이트가 대상 사업을 운영한다**는 뜻이지, 다른 연령이 지원할 수 없다는 뜻은 아니다. 화면 문구도 그렇게 쓴다.
- `무관`은 경력 구분을 가리지 않는다는 뜻이다.
- 자격·면허가 필수인 곳(메디컬잡 등)은 `자격증`·`면허`를 함께 둔다.

### 4-3. `needs` — 내담자 상황·목표 (7갈래 · 27묶음)

내담자가 «무엇을 하려는데 어디서 찾아야 할지 모를 때» 한 번 고르는 갈래다. `goals`의 하위 코드(`kids`)만 쓴다.

| 갈래 | 하위 묶음 |
|---|---|
| `job` 일자리·공고 찾기 | `job_new` 신입·공채 · `job_move` 경력·이직 · `job_pub` 공공·공기업·공무원 · `job_tech` IT·스타트업 · `job_short` 알바·단기 · `job_global` 해외·외국계 · `job_local` 지역 일자리 |
| `explore` 진로·직업 탐색 | `exp_test` 진로·직업심리검사 · `exp_dict` 직업사전·신직업 · `exp_stats` 산업전망·통계 |
| `train` 훈련·자격·교육 | `trn_gov` 국비훈련·내일배움카드 · `trn_cert` 국가·민간자격 · `trn_online` 온라인 직무교육 · `trn_degree` 학위·평생학습 |
| `support` 지원금·고용행정·권리 | `sup_ui` 실업급여·국취제 · `sup_labor` 임금·근로조건·노무 · `sup_welfare` 복지·생활지원 |
| `research` 기업 조사·서류·면접 | `corp_fin` 공시·재무·투자 · `corp_culture` 연봉·조직문화 · `corp_doc` 자소서·면접·취업정보 |
| `start` 창업·N잡·프리랜서 | `biz_start` 창업지원·투자 · `biz_freel` 프리랜서·외주 |
| `audience` 대상별 맞춤 창구 | `aud_youth` 청년 · `aud_mid` 중장년·시니어 · `aud_women` 경력단절여성 · `aud_disabled` 장애인 · `aud_foreign` 외국인·다문화·북한이탈 |

- 한 사이트가 여러 갈래에 걸치면 `needs`에 모두 적되(최대 4개), **첫 값을 대표 목적**으로 삼는다. 화면은 「상황·목표」로 묶을 때 대표 목적 한 묶음에만 놓아 같은 카드가 두 번 나오지 않게 한다.
- 모든 하위 코드에는 사이트가 **한 곳 이상** 있어야 한다(빈 묶음 금지 — `validate.py`가 잡는다).

### 4-4. `owner` — 운영 주체

`gov`(정부·공공기관) · `corp`(기업·그룹·단체 채용관) · `biz`(민간 포털·서비스). 상담에서 「공공 창구인지 민간 서비스인지」를 먼저 가르는 기준이다.

## 5. 검증 정책 (데이터를 고칠 때 지킬 것)

1. **모든 `url`은 실제 접속으로 최종 200을 확인한 뒤 넣는다.** 3xx는 리다이렉트를 따라간 최종 응답이 200이어야 한다.
2. 자동 접속을 막는 사이트(403)는 **실제 브라우저로 화면이 뜨는지** 확인하고 `verify_method: "browser"`로 남긴다. 브라우저에서도 막히면 넣지 않는다.
3. **해외·클라우드망에서만 차단되는 국내 정부 포털**은 `verify_method: "official"`, `http_status: null`, `verify_note`로 수록한다(5-3).
4. 접속되지 않는 곳(시간 초과·TLS 오류·도메인 판매·폐쇄)은 **`meta.verification.excluded`에 이름·주소·사유를 남기고 목록에서 뺀다.** 조용히 지우지 않는다.
5. 이름이 비슷한 유인 사이트(도메인 판매 페이지, 다른 회사)를 실제 사이트로 착각하지 않는다. 응답 본문의 제목으로 확인한다.
6. `verified_at`은 **그 항목을 실제로 확인한 날**이다. 일부만 확인하고 날짜만 올리지 않는다 — 확인하지 못한 항목은 앞서 확인한 날짜를 그대로 둔다.

### 5-3. `official` 검증 등급 (2026-11-19 신설)

- 대상: `www.cleaneye.go.kr`(클린아이), `job.cleaneye.go.kr`(잡플러스), `local.gosi.go.kr`(지방자치단체 인터넷원서접수센터).
- 사정: 셋 다 행정안전부가 운영하는 공식 포털이고 주소는 공식 공표로 확인되지만, **해외·클라우드망에서 TCP 연결이 차단**되어 우리 검증 환경에서는 응답을 볼 수 없다(국내망에서는 정상). 여러 해외 노드에서도 같은 결과였다.
- 그래서 **200을 확인했다고 적지 않는다.** `http_status: null`, `verify_method: "official"`, `verify_note`에 근거와 제한을 적고, 화면은 카드에 「국내 접속」, 상세에 「공식 안내로 확인」 도장과 안내 문장을 보여 준다.
- 이 등급은 **국내 사용자에게 실제로 열리는 공식 사이트**를 목록에서 빼지 않기 위한 장치다. 확인 없이 아무 사이트나 이 등급으로 넣지 않는다 — 공식 공표(부처 보도자료·시스템 안내)로 주소가 확인되어야 한다.
- **현재 상태(2026-11-23)**: 세 사이트 모두 검증 환경에서 브라우저로 직접 화면을 확인할 수 있어 200·`browser`로 기록했다. `official` 등급은 제도로 남겨 두고, 다시 막히면 같은 기준으로 돌아간다.

## 6. 화면이 지킬 제약

- **공고 본문·공시 자료·로고·슬로건을 옮기지 않는다.** 화면에 보이는 설명은 이 JSON의 `strengths`·`shows`·`tips` 문장뿐이다. 사이트 화면을 캡처해 붙이지 않는다.
- **내보내기 금지** — 저장·인쇄·PDF·복사 버튼을 만들지 않는다.
- 외부 링크는 `target="_blank" rel="noopener noreferrer"`로 새 탭에서 연다.
- 데이터에 없는 값(공고 수, 평점, 채용 중 여부)을 화면에서 만들지 않는다.
- 상세에는 `operator`·`verified_at`(검증일)·`roles`·`eligibility`·`shows`를 그대로 노출해, "언제 확인한 정보인지·가서 무엇을 볼 수 있는지"를 사용자가 알 수 있게 한다.
- `verify_method: "official"` 항목은 카드에 「국내 접속」, 상세에 「공식 안내로 확인」과 `verify_note`를 보여 준다.
- 10개 대분류 + `roles` + `eligibility`의 **교차 필터**가 이 데이터의 핵심 용도다. 필터는 주소(hash)에 남겨 새로고침·공유에 견디게 한다.
- **묶어 보기**: 「상황·목표(`goals`)·대분류·직무·대상·운영 주체」 가운데 하나를 고르면 결과를 **묶음 머리글 + 건수**로 나누고, 「상황·목표」에서는 하위 묶음(`kids`)까지 한 단계 더 나눈다. 머리글을 눌러 접고 펼친다. 고른 기준은 hash의 `g=`에 남긴다. 사이트는 **대표 목적 한 묶음에만** 놓아 같은 카드가 두 번 보이지 않게 한다.
- **검색은 이름·운영 주체·특징뿐 아니라 도메인·영문 약어·`aliases`로도 걸린다.** `?q=`로도 검색어를 받는다.
