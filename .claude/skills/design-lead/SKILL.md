# design-lead — 디자인 리드 루틴

새 섹터 개발, 기존 섹터 디자인 개편, 공용 층(`assets/prefs.js`) 변경 전에 이 순서를 밟는다.
먼저 `DESIGN.md`(§0 가드레일·§1~§3 원칙·토큰)와 해당 유형의 `design/patterns/*.md`, 최신 `design/studies/` 노트 1~2개를 읽는다.

이 루틴은 **한 번 통과하는 절차가 아니라 진화 루프**다. ⑦에서 남긴 기록이 다음 작업의 ①로 들어간다.

## ① 비지시적 탐색 — 웹 밖에서도 원리를 찾는다

답을 정해 놓고 근거를 찾는 방식(확증 탐색)을 쓰지 않는다. 먼저 원리를 모으고, 그다음에 무엇을 만들지 정한다.

- **웹(2~3곳)**: Codrops(tympanus.net/codrops), CSS-Tricks, Godly, Siteinspire, Awwwards, 보조로 web.dev·MDN·Smashing Magazine·Josh W. Comeau·Chrome Developers 블로그. 최근 12개월 글·작품 1개 이상 포함.
- **웹 밖(1곳 이상)**: 인쇄 편집(신문 지면·도록·문학책 판형), 지도·항로표·철도 시간표, 악보, 게임 UI(인벤토리·스킬 트리·맵), 전시 안내판, 백화점 카탈로그. 이 매체들을 **실제로 열어 보거나 손에 있는 자료를 보고** 원리를 적는다.
- **찾는 것(모양이 아니라 원리)**: 반복 단위를 어떻게 정하는가 / 위치 감각을 무엇으로 주는가 / 같은 정보를 어떤 순서로 접는가 / 리듬을 무엇으로 만드는가 / 밀도가 높은데 읽히는 이유는 무엇인가.
- **검색어 예**: `codrops progressive disclosure`, `css-tricks accordion animation transform`, `web.dev animations guide compositor`, `editorial grid newspaper layout principle`, `transit map information density`, `game ui inventory grid readability`.
- 출처마다 URL·날짜·한 줄 요지를 적는다. 옮겨 적지 않는다.

## ② 지적재산권 필터 — 통과한 것만 쓴다 (가장 엄격하게)

**애매한 것도 지적재산권·트레이드 드레스·디자인권에 걸릴 수 있다.** 확신이 없으면 쓰지 않는다. 이 필터를 통과하지 못한 것은 ③ 시안에도 넣지 않는다.

### 통과 판정 — 세 질문 (하나라도 「그렇다」면 탈락)
1. 이 배치·구성을 보면 **특정 서비스가 떠오르는가?**
2. 그 서비스**만의 조합**인가(레이아웃 + 색 + 모션 + 아이콘 + 문구가 함께 상징이 되는가)?
3. 두 화면을 나란히 놓았을 때 **출처를 짚을 수 있는가?**

### 해도 되는 것 / 절대 하지 않는 것
| 해도 되는 것 (일반 원리만) | 절대 하지 않는 것 |
|---|---|
| 레이아웃 비례(1.05:1 두 단, 8pt 격자), 위계 순서 | 이미지·일러스트·사진·로고 복제나 핫링크 |
| 색 대비 관계(밝기 차, 강조 1색 원칙) | 웹폰트 파일 복사, 유료 폰트 사용 |
| 모션 원리(무엇이 언제 어느 방향으로, 길이·곡선 범위) | 데모 코드·CSS를 그대로 붙여 넣기, 클래스 이름 체계 베끼기 |
| 상호작용 패턴(펼침 손잡이, 시트, 단계 표시) | 특정 사이트의 시그니처 화면을 알아볼 수 있게 재현 |
| 일반 공개 표준 문서의 API 사용법(MDN·WCAG) | 글 문단 번역·인용을 노트에 길게 옮기기(15단어 넘는 인용 금지) |
| 스크린샷을 **보고 원리만 적기** | 스크린샷을 **보고 그리기**(트레이스), 화면 재현 |

- 특정 앱의 유명 인터랙션을 이름까지 따라가며 만드는 것도 금지다(카드 스택, 책장 넘김의 특정 연출 등 **그 서비스가 상징처럼 쓰는 형태**).
- 「비슷하게」는 허용되지 않는다. **같은 원리를 우리 자료 구조에 맞게 새로 설계**하면 결과가 달라야 정상이다.
- 노트에는 **자기 말로 추상화한 원리**와 **우리 저장소용으로 새로 쓴 패턴(코드 조각 포함)** 만 남긴다.
- 판단이 섰다면 노트에 **어디서 멈췄는지** 한 줄 남긴다(예: 「A사 카드 스택은 형태가 상징이라 참고하지 않음」).

## ③ 변이 — 시안 2~3개를 짧게 겨룬다

- 새 섹터·대개편: **서로 다른 메타포·레이아웃 2~3안**. 한 안에 30분을 넘기지 않는다(한 화면 HTML 한 파일 또는 종이 스케치 사진).
- 각 안을 셋으로 평가한다.
  - **밀도** — 첫 화면에서 결론이 보이는가.
  - **직관성** — 처음 본 사람이 다음에 누를 것을 아는가, 휴대폰에서 한 손으로 닿는가.
  - **확장성** — 자료가 2배로 늘어도 무너지지 않는가.
- 채택은 하나. 채택·탈락 사유를 노트의 「시안 비교」 절에 한 줄씩 남긴다. 탈락한 안도 버리지 않고 사유와 함께 둔다(다음 변이의 재료).
- 작은 수정에는 ③을 생략할 수 있다. 새 섹터·대개편에는 생략하지 않는다.

## ④ 학습 노트 (`design/studies/YYYY-MM-DD-주제.md`)

형식:
```
# 주제 — 날짜
## 탐색한 곳
- [제목](URL) · 날짜 · 한 줄 요지(자기 말)
- (웹 밖) 자료 이름 · 본 것 · 한 줄 요지
## 추상화한 원리
1. 원리 — 왜 통하는가 — 가드레일과 충돌 여부
## 자체 작성 패턴
- 이름 / 쓰는 곳 / 코드 조각(직접 쓴 것) / 접근성·감속 모드 처리
## 시안 비교 (새 섹터·대개편)
- 안 A / B / C — 밀도·직관성·확장성 / 채택과 사유
## 이번 작업에 적용할 곳
- 파일 · 선택자 · 기대 효과
## 지재권 기록
- 참고한 것 / 쓰지 않기로 한 것과 이유
```
- 적용 후 해당 `design/patterns/*.md`에 한 절로 옮기고, `DESIGN.md` §11 인덱스에 한 줄만 더한다.

## ⑤ 구현 원칙 (DESIGN.md 요약)

- 90:10, 휴대폰 세로/큰 화면 가로 별도 설계, 초면 핵심·키워드 → 상호작용 세부, `transform`·`opacity` 모션만.
- 섹터 개수 고정 금지, 유머 문구 금지, 집중 보기에서는 장식 해제.
- 손맛 규칙(44px, 백지 프레임, 프레임 간격)은 `design/patterns/touch-physics.md`.

## ⑥ 손맛 실측 검수 — 헤드리스 브라우저로 숫자를 낸다

구현 후 반드시 돌린다. 먼저 공용 검수 `node ops/qa/audit.js <경로>`(오류·넘침·44px·화면 분량·대기 rAF)를 돌리고, 손맛처럼 섹터마다 다른 시험은 세션 작업 폴더에 새로 만든다(저장소에 넣지 않는다).
「느낌」으로 통과시키지 않는다. 숫자를 커밋 메시지와 `design/HANDOFF.md`에 적는다.

### 6-1. 기존 항목

| 항목 | 방법 | 통과 기준 |
|---|---|---|
| **모바일 세로** | 390×844, 360×780, 글자 0·2단계 | 가로 넘침 0, 콘솔 오류 0, 첫 화면 텍스트 글자 수 측정(보이는 글자만) → 앞보다 줄었거나 예산 안 |
| **큰 화면 가로** | 820×1180, 1180×820, 1280×800, 1600×900 | 가로 배치가 실제로 2단 이상, 오른쪽이 텅 빈 구간 없음 |
| **화면 분량(무의미한 세로 스크롤)** | 폭마다 `scrollHeight ÷ innerHeight`, 탭·카드를 바꿔 가며 최댓값 | 큰 화면 ≤ 1.5, 휴대폰 ≤ 2.5. 넘으면 다단·목록-상세·탭으로 다시 짠다(긴글 읽기 화면은 예외, 사유 기록) |
| **가로 휴대폰** | 844×390 | 머리말이 화면 절반 넘게 덮지 않음 |
| **초면 텍스트 밀도** | 첫 화면 안에 보이는 텍스트 노드 글자 수(`getClientRects` + 조상 `opacity`·`visibility` 확인) | 휴대폰 첫 화면 본문 3줄·카드 80자 권장 |
| **모션 가드레일** | ① CSS에서 금지 속성 `transition`·`@keyframes` 검색 ② 3초 가만히 두고 rAF 호출 수 측정 | ① 0건 ② 상시 루프 0 |
| **감속 모드** | `reducedMotion='reduce'` | 꾸밈 애니메이션 0, 기능 정상 |
| **집중 보기** | `JCPrefs.immersive.on()` → 스크린샷 → `off()` | 장식 숨김, 도구함 보임, 끈 뒤 `data-jc-imm` 잔여 0 |
| **90:10 체감** | 스크린샷을 직접 본다 | 손맛 포인트 2~3개, 본문 구역은 깨끗함. AI 템플릿처럼 보이지 않음 |
| **대비** | 보조 글자색 계산 | 4.5:1 이상 |

### 6-2. 손맛 실측 항목 (터치·드래그·전환)

| 항목 | 방법 | 통과 기준 |
|---|---|---|
| **백지 프레임** | CDP `Page.startScreencast`(매 프레임, JPEG)로 전환(넘김·펼침·모드 전환) 동안 프레임을 모은다. 각 프레임에서 본문 영역을 표본 픽셀로 훑어 **한 가지 색으로만 채워진 프레임**(휘도 최대−최소 < 6)을 센다. 끌기·단추·키보드 세 경로를 각각 10회 | **0장**. 1장이라도 나오면 원인(면 재생성·시계 시작 위치·z 분리)을 고치고 다시 잰다 |
| **프레임 간격 스파이크** | 페이지 안에서 `requestAnimationFrame` 타임스탬프를 수집하며, 스크립트로 끌기(pointer 이벤트 12단계)와 전환을 실행. 간격의 p50·p95·최대를 계산 | p95 ≤ 33.4ms(60Hz 2프레임), 최대 ≤ 50ms, 100ms 이상 멈춤 0회 |
| **터치 타깃 44px** | `a,button,select,input,summary,[role=button],[tabindex]`의 `getBoundingClientRect` | 누를 수 있는 것 전부 44×44 이상. 문장 속 인라인 링크만 예외(목록으로 남김). 단추 사이 간격 8px 이상 |
| **연속 입력 반응 지연** | 필터·검색 입력에 초당 8타를 넣고, `input` 이벤트에서 다음 페인트(결과 갱신 후 첫 rAF)까지 시간을 20회 측정. `PerformanceObserver('longtask')`로 50ms 넘는 작업도 함께 | 지연 p95 ≤ 50ms, 100ms 넘는 긴 작업 0회, 입력 글자가 한 박자 늦게 뜨지 않음 |
| **드래그 반응 첫 프레임** | `pointerdown`→`pointermove` 첫 반응까지 프레임 수 | 1프레임(≈16.7ms) 이내. 임계값 전에는 아무것도 움직이지 않음 |
| **전환 후 잔여물** | 전환·모드 변경·`resize`·탭 전환 뒤 DOM 확인 | 낱장·오버레이·`will-change`·`busy` 잠금 잔여 0 |
| **Safari 대체 동작** | `@starting-style` 미지원 브라우저(WebKit 구형 흉내: 규칙 무효) | 즉시 표시, 깜빡임 없음, 기능 정상 |
| **키보드·스크린리더 트리** | `aria-expanded`, 닫힌 영역 `hidden`/`inert`, 초점 순서 | 펼침 상태 반영, 초점이 숨은 요소로 가지 않음 |

- 항목별 숫자는 `design/studies/`나 HANDOFF에 **측정 조건(폭·테마·경로·반복 횟수)과 함께** 남긴다. 조건 없는 숫자는 다음 세션에서 재현할 수 없다.
- 실기기(아이폰 사파리, 갤럭시 Chrome·삼성 인터넷, 폴더블)는 헤드리스로 대신할 수 없다. 확인 못 한 항목은 HANDOFF·PR 본문에 「실기기 확인 필요」로 남긴다(헤드리스 WebKit은 GPU가 없어 3D 층 체감을 대신하지 못한다).

## ⑦ 선택과 도태 — 결과를 체계로 되돌린다

- **적중**: 태화님이 채택·호평한 패턴은 `DESIGN.md` §9 적중 이력의 이력 칸을 올리고, 해당 모듈에 「왜 통했는지」 한 줄을 더한다.
- **도태**: 실기기에서 「덜컹 / 답답 / 구림」 피드백을 받은 요소, 또는 ⑥에서 기준을 못 넘은 구현은 `DESIGN.md` §10 도태 목록에 (증상·대체·날짜)로 적는다. **같은 형태로 다시 제안하지 않는다.** 변형해 다시 쓸 때는 도태 사유를 어떻게 피했는지 노트에 적는다.
- 규칙은 늘리기만 하지 않는다. 쌓인 지식은 모듈로, `DESIGN.md`에는 요약만. 더 이상 쓰이지 않는 규칙은 지운다(지운 이유는 도태 목록에).

## ⑧ 마무리
- 해당 `design/patterns/*.md`에 노하우 누적 → `DESIGN.md` §9·§10·§11 한 줄 → `design/HANDOFF.md` 갱신 → 단계별 커밋.
- 커밋 메시지에 ⑥의 실측 숫자를 적는다(예: `백지 프레임 0, 프레임 간격 p95 21ms, 44px 미달 0`).
