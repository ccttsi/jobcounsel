# design-lead — 디자인 리드 루틴

새 섹터 개발, 기존 섹터 디자인 개편, 공용 층(`assets/prefs.js`) 변경 전에 이 순서를 밟는다.
먼저 `DESIGN.md` 전체와 `design/studies/`의 최신 노트 1~2개를 읽는다.

## ① 레퍼런스 탐색 (직접 웹 탐색, 2~3곳)

- 대상(돌아가며 고른다): **Codrops**(tympanus.net/codrops), **CSS-Tricks**, **Godly**, **Siteinspire**, **Awwwards**, 보조로 web.dev·MDN·Smashing Magazine·Josh W. Comeau·Chrome Developers 블로그.
- 무엇을 찾나: 이번 작업과 관련된 **원리** 한두 가지 — 예) 점진적 공개, 펼침 모션, 게이지·채우기, 요소 생성·전개, 카드 밀도, 가로/세로 분할, 편집 디자인식 위계.
- 검색어 예: `codrops progressive disclosure`, `css-tricks accordion animation transform`, `web.dev animations guide compositor`, `awwwards editorial layout`, `view transitions api`.
- 가능하면 **최근 12개월 안의** 글·작품을 1개 이상 포함한다.
- 출처마다 URL·날짜·한 줄 요지를 적어 둔다.

## ② 저작권 안전 필터 (통과한 것만 쓴다)

| 해도 되는 것 | 절대 하지 않는 것 |
|---|---|
| 레이아웃 비례(예: 1.05 : 1 두 단, 8pt 격자), 위계 순서 | 이미지·일러스트·사진·로고 복제나 핫링크 |
| 색 대비 관계(밝기 차, 강조 1색 원칙) | 웹폰트 파일 복사, 유료 폰트 사용 |
| 모션 원리(무엇이 언제 어느 방향으로, 길이·곡선 범위) | 데모 코드·CSS를 그대로 붙여 넣기, 클래스 이름 체계 베끼기 |
| 상호작용 패턴(펼침 손잡이, 시트, 단계 표시) | 특정 사이트의 시그니처 화면을 알아볼 수 있게 재현 |
| 일반 공개 표준 문서의 API 사용법(MDN 등) | 글 문단 번역·인용을 노트에 길게 옮기기(15단어 넘는 인용 금지) |

- 노트에는 **자기 말로 추상화한 원리**와 **우리 저장소용으로 새로 쓴 패턴(코드 조각 포함)** 만 남긴다.
- 의심스러우면 쓰지 않는다.

## ③ 학습 노트 (`design/studies/YYYY-MM-DD-주제.md`)

형식:
```
# 주제 — 날짜
## 탐색한 곳
- [제목](URL) · 날짜 · 한 줄 요지(자기 말)
## 추상화한 원리
1. 원리 — 왜 통하는가 — 가드레일과 충돌 여부
## 자체 작성 패턴
- 이름 / 쓰는 곳 / 코드 조각(직접 쓴 것) / 접근성·감속 모드 처리
## 이번 작업에 적용할 곳
- 파일 · 선택자 · 기대 효과
```
- 적용 후 `DESIGN.md` 「패턴 기록」에 한 단락으로 옮긴다.

## ④ 구현 원칙 (DESIGN.md 요약)

- 90:10, 휴대폰 세로/큰 화면 가로 별도 설계, 초면 핵심·키워드 → 상호작용 세부, transform·opacity 모션만.
- 섹터 개수 고정 금지, 유머 문구 금지, 집중 보기에서는 장식 해제.

## ⑤ 셀프 검수 루틴 (구현 후, 결과를 커밋 메시지나 HANDOFF에 적는다)

헤드리스 크롬(Playwright)으로 아래를 돌린다. 시험 스크립트는 세션마다 `tools/`가 아니라 작업 폴더 밖(`/home/claude/tools/`)에 새로 만든다.

| 항목 | 방법 | 통과 기준 |
|---|---|---|
| **모바일 세로** | 390×844, 360×780, 글자 0·2단계 | 가로 넘침 0, 콘솔 오류 0, 초면(첫 화면 높이 안) 텍스트 글자 수 측정 → 앞보다 줄었거나 예산 안 |
| **큰 화면 가로** | 820×1180, 1180×820(폴더블·태블릿), 1280×800, 1600×900 | 가로 배치가 실제로 2단 이상, 오른쪽이 텅 빈 구간 없음 |
| **가로 휴대폰** | 844×390 | 머리말이 화면 절반 넘게 덮지 않음 |
| **초면 텍스트 밀도** | 첫 화면 안에 보이는 텍스트 노드 글자 수 | 휴대폰 첫 화면 본문 3줄·카드 80자 권장 |
| **무랙 모션** | ① CSS에서 금지 속성 `transition`/`@keyframes` 검색 ② 페이지를 3초 가만히 두고 rAF 호출 수 측정 | ① 0건 ② 상시 루프 0(스크롤·포인터 없을 때 rAF 0) |
| **감속 모드** | `reduced_motion='reduce'` | 꾸밈 애니메이션 0, 기능 정상 |
| **집중 보기** | `JCPrefs.immersive.on()` → 스크린샷 → `off()` | 장식 숨김, 도구함 보임, 끈 뒤 `data-jc-imm` 잔여 0 |
| **90:10 체감** | 스크린샷을 직접 본다 | 손맛 포인트 2~3개가 보이고, 본문 구역은 깨끗함. AI 템플릿처럼 보이지 않음 |
| **대비** | 보조 글자색 계산 | 4.5:1 이상 |

- 실기기(아이폰 사파리, 갤럭시 Chrome·삼성 인터넷, 폴더블)는 헤드리스로 대신할 수 없다. 확인 못 한 항목은 HANDOFF·PR 본문에 「실기기 확인 필요」로 남긴다.

## ⑥ 마무리
- `DESIGN.md` 패턴 기록 누적, `design/HANDOFF.md` 갱신, 단계별 커밋.
