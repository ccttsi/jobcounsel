# start — 시작 루틴

태화님이 `/start` 또는 "시작"이라고 하면 아래를 순서대로 하고, 끝에 **3~5줄 요약 + 오늘 추천 작업 1~2개**를 보여 준다. 사용자가 고를 때까지 코드를 고치지 않는다.

## 1. 저장소 최신화
- `git fetch --depth=50 origin main` 후 `main` 최신에서 새 브랜치를 판다(작업 내용이 정해진 뒤).
- 열린 PR 확인: `gh api repos/ccttsi/jobcounsel/pulls --jq '.[] | "#\(.number) \(.head.ref) \(.title)"'` (`gh pr list`는 이 환경에서 막혀 있다).
- 원격 작업 브랜치 확인: `git ls-remote --heads origin` — 다른 세션이 진행 중인 브랜치가 고치는 파일은 건드리지 않는다.

## 2. 노션 읽기 (Notion 연결 사용)
1. 가장 최근 핸드오프 페이지: 노션에서 「핸드오프」로 검색해 최신 것 하나. 「지금 백그라운드에서 돌고 있는 작업」과 「손대지 말 것」을 먼저 본다.
2. 자료실 섹터 보드 — `collection://e1d730f4-4d70-4909-b181-1645161b9791` 에서 상태가 `작업대기`·`진행중`·`PR`인 항목.
3. 📒 직업상담 자료실 개발일지 — https://app.notion.com/p/41a14d0ef5508122aa10dd376742a5a4 맨 아래 3~5개 항목.
4. 🎨 DESIGN.md(노션 사본)는 읽지 않는다. 기준은 저장소의 `DESIGN.md`다.

## 3. 저장소 문서
- `design/HANDOFF.md`의 [남은 작업 / 다음 시작 파일].
- 작업이 정해지면 `CLAUDE.md` 「작업 시작 전」 목록대로 해당 유형 모듈만 읽는다.

## 4. 우선순위
1. 태화님 실기기 피드백(「덜컹·답답·구림」 등)
2. 보드의 `작업대기` 중 다른 세션과 파일이 겹치지 않는 것
3. HANDOFF의 남은 부채(예: 터치 44px 미달)
