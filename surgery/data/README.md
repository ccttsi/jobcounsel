# 서류·공고 해부실 데이터 (surgery-anatomy v1.0.0)

직업상담 자료실(`ccttsi/jobcounsel`)의 **20번 「서류·공고 해부실 (자소서·이력서·채용공고 매스)」** 이 쓰는 데이터셋입니다.
자소서·이력서·채용공고를 **대신 써 주는** 데이터가 아니라, **어디가 문제인지 갈라 보여 주는** 데이터입니다.

- 만든 날: **2026-11-16**
- 수록: 공고 문구 **28종** · 탈락 문장 **22종** · 상황별 이력서 **6종** · 내부 키워드 **225개**(45묶음) · 톤 **4종** × 용도 2 × 문형 3 = **24문형**
- 형식: UTF-8(JSON) 2개 파일 + 계약서 + 검증 스크립트
- 검증: `python3 surgery/data/validate.py` → **오류 0건, 경고 0건**

| 파일 | 내용 | 노출 |
|---|---|---|
| `anatomy.json` | 공개 해부학 데이터 — 공고 문구 · 탈락 문장 · 이력서 배치 | 화면에 그대로 씀 |
| `lexicon.json` | **비노출 내부 키워드 매핑 DB** — 조립 엔진만 읽는다 | **화면 노출 금지** |
| `SCHEMA.md` | 화면 구현 계약 — 필드·어휘·조립 알고리즘·UI 제약 | 개발 문서 |
| `validate.py` | 구조 검증 + 조립 엔진 참조 구현(`--selftest`) | 개발 도구 |
| `README.md` | 이 문서 — 수록 범위·방법·한계 | 문서 |

## 1. 무엇이 들어 있나

### ① 채용공고 해부학 (28종)

공고에서 흔히 보는 표현을 절개해 **숨은 의도 · 맹점 역공 포인트 · 신호등**으로 나눕니다.

| 신호 | 뜻 | 건수 |
|---|---|---:|
| 🟢 `green` 뚫을 신호 | 문구가 사실이면 유리한 조건 | 5 |
| 🟡 `yellow` 확인 필요 | 좋게도 나쁘게도 읽힘 | 16 |
| 🔴 `red` 레드플래그 | 지원 전에 조건 확인 | 7 |

다루는 범주 6가지: 역량 과장·상투어 · 근무조건·보상 · 조직문화·관계 · 경력·자격·대상 · 성장·비전 · 업무범위.

각 항목은 "이 문구는 이렇게 읽힌다"(숨은 의도) → "그래서 무엇을 보여 줄까"(어필) → "무엇을 물어볼까"(역공 질문) → "무엇을 확인할까"(확인 항목)로 이어집니다.
예: 「야근·특근 가능자(협의)」는 🔴로 두고, 초과근무 실태와 특근 보상 방식을 묻는 질문을 붙였습니다.

### ② 탈락 문장 X-선 & 직무 번역 (22종)

흔한 추상·감점 문장을 투과해 **왜 감점인지**를 보여 주고, **CAR/STAR·수치 기반 문장**으로 다시 쓴 예시를 붙였습니다.

다루는 테마: 지원동기 · 성장과정 · 성격의 장점 · 단점 · 열정 · 소통 · 성실 · 리더십 · 팀워크 · 갈등 · 실패 · 입사 후 포부 · 직무 적합성 · 경력 공백 · 이직 사유 · 아르바이트 경험 · 전공 불일치 · 수상·자격 · 봉사 · 프로젝트 성과 · 마무리 각오 · 장기 비전.

각 항목은 `before`(감점 문장) · `xray_diagnosis`(감점 원인) · `rule`(교정 원칙) · `after_star`(재작성 예시) · `star`(S/T/A/R 네 줄) · `metric_hint`(넣어야 할 숫자 유형)로 되어 있습니다.

### ③ 상황별 이력서 재배치 (6종)

| 상황 | 추천 포맷 | 섹션 우선순위(앞→뒤) |
|---|---|---|
| 공백기 1년+ | 혼합형 | 프로필 → 핵심 역량 → **공백기 해명** → 경력 → 프로젝트·성과 → 교육·훈련 → 자격·어학 |
| 비전공 직무전환 | 기능형 | 프로필 → 핵심 역량 → **교육·훈련** → 프로젝트·성과 → 경력 → 자격·어학 |
| 경력단절(재취업) | 기능형 | 프로필 → 핵심 역량 → 경력 → 공백기 해명 → 교육·훈련 → 자격·어학 |
| 단기 알바·파견 위주 | 혼합형 | 프로필 → 핵심 역량 → **프로젝트·성과** → 경력 → 교육·훈련 → 자격·어학 |
| 스펙·자격 공백 신입 | 기능형 | 프로필 → 핵심 역량 → **교육·훈련** → 프로젝트·성과 → 봉사·대외활동 → 자격·어학 |
| 중장년 재취업 | 혼합형 | 프로필 → 핵심 역량 → 경력 → 교육·훈련 → 자격·어학 → 프로젝트·성과 |

상황마다 **방어 공식 2~3종**(질문 → 공식 → 예시)과 그 상황에서 흔히 하는 실수(`cautions`)를 붙였습니다.
예: 공백기는 "기간 + 한 일 + 얻은 것 + 직무 연결" 공식, 경력단절은 "사실 + 그동안 유지한 것 + 지금 상태" 공식.

### ④ 문장 수술실 — 내부 키워드 DB (`lexicon.json`)

단어 하나(또는 몇 개)를 넣으면 그 단어를 **역량 · 행동 · 수치 슬롯으로 해체해 다시 조립**하여, 톤앤매너별 문장 **2~4개**를 만듭니다.

- 45묶음 · 키워드 225개 — 알바/서비스(편의점·카페·서빙·CS·콜센터·판매·물류), 사무/행정(엑셀·문서·총무·회계·일정·보고서·기록·인사), 대외/협업(동아리·조별과제·봉사·학생회·멘토링·행사·갈등·리더십), 기술/제작(코딩·디자인·영상·데이터·마케팅·SNS·글쓰기·리서치·자동화), 성향/상황(성실·꼼꼼·소통·갈등·실패·주도·공백기·이직·압박·학습·적응·계획·친절)
- 톤 4종: 성과·수치형 / 문제해결·논리형 / 협업·조율형 / 성실·안정형
- 용도 2종: 이력서 한 줄 / 자소서 핵심 문단
- 폴백 2단: 부분 일치 → 범주 폴백 → 일반 폴백. **모르는 단어(`우주정거장`)를 넣어도 문장 2~4개가 나옵니다.**

**비노출 원칙**: 이 파일의 키워드 목록·매핑표는 화면 메뉴·목록·검색 결과 어디에도 펼치지 않습니다. 화면은 조립된 문장과 "이 단어를 이렇게 해석했다" 한 줄만 보여 줍니다. 단어 목록을 보여 주면 사용자가 매핑표를 외워 문장을 짜깁기하게 되고, 자기 경험을 확인하는 과정이 사라지기 때문입니다.

## 2. 어떻게 만들었나 (저작권 원칙)

- **100% 자체 구조화**입니다. 외부 유료 AI API를 쓰지 않았고, **타인의 실제 합격 자소서나 특정 회사의 채용공고 원문을 옮기지 않았습니다.**
- 공고 문구는 **업계 공통 상투어**를 자료실이 정리한 것이고, `before` 문장과 `after_star` 예시는 **자료실이 직접 쓴 것**입니다.
- 회사명·직무명·합격 사례·인재상 문구는 데이터에 없습니다. 화면도 만들지 않습니다.
- 화면은 **내보내기(저장·인쇄·PDF·복사) 버튼을 두지 않습니다.** 이 도구의 목적은 남의 문장을 가져가는 것이 아니라 자기 문장을 다시 쓰는 것입니다(`DESIGN.md` §0, PR #49·#52).
- 문장 예시의 `[숫자]`·`[기간]`은 **사용자가 자기 사실로 채우는 자리**입니다. 데이터는 그 자리를 임의로 채우지 않습니다.

## 3. 한계

- **합격을 보장하지 않습니다.** 감점 요인과 교정 원칙을 보여 주는 학습·상담 자료입니다.
- **회사별 인재상 데이터는 없습니다.** "회사가 요구하는 인재상에 맞춘 톤"은 사용자가 공고에서 고른 키워드와 톤 선택으로 결정합니다. 회사별 인재상 문구 DB는 20-1 후보입니다.
- **문구 해석은 단정이 아닙니다.** `hidden_intent`는 "~일 수 있다" 수준의 읽기이며, 실제 조건은 면접·현직자·공고 원문으로 확인해야 합니다. 신호등은 회사 평가가 아닙니다.
- **키워드 225개는 전부가 아닙니다.** 45묶음 밖의 생소한 단어는 범주 폴백·일반 폴백으로 처리하므로, 문장이 일반적일 수 있습니다. 그때는 사용자가 `context`와 숫자를 직접 바꿔야 합니다.
- **조립 문장은 결정적입니다.** 같은 입력에 같은 문장이 나오도록 난수를 쓰지 않습니다. 표현의 다양성이 필요하면 사용자가 톤을 바꿔 여러 번 조립합니다.
- **이력서 배치 6종은 대표 상황만** 다룹니다. 산업별·직무별 세부 양식(연구직 CV, 의료·교육 자격 이력서 등)은 다루지 않았습니다.

## 4. 검증

```bash
python3 surgery/data/validate.py
# surgery/data  ·  검증일 2026-11-16
#    anatomy.json  ·  jd_anatomy 28종 (green 5 / yellow 16 / red 7)  ·  xray_cases 22종  ·  resume_layouts 6종
#    lexicon.json  ·  entries 45  ·  trigger_keywords 225  ·  tone_frames 4  ·  templates 24  (비노출)
# 오류 0건, 경고 0건

python3 surgery/data/validate.py --selftest
# 알려진 단어·모르는 단어·범주 힌트로 항상 2~4문장이 나오는지, 슬롯이 남지 않는지, 같은 입력에 같은 출력인지 확인
```

`validate.py`의 `assemble()`은 화면이 구현할 조립 규칙의 **참조 구현**입니다. 화면 결과가 이와 다르면 조사 처리(`fix_particles`)나 순환 순서를 먼저 확인하세요.

## 5. 화면(`/surgery/`)을 만들 때

1. `SCHEMA.md`를 먼저 읽고, 스키마에 없는 값을 화면에서 만들지 않는다.
2. `anatomy.json`만 화면 데이터로 쓴다. `lexicon.json`은 조립 엔진 내부에서만 읽는다.
3. 모션은 `transform`·`opacity`만(`DESIGN.md` §2). 재배치·절개·투과 모션은 GPU 합성 속성으로만 만들고, `prefers-reduced-motion`에서 멈춘다.
4. 분량: 큰 화면 ≤ 1.5화면, 휴대폰(390px) ≤ 2.5화면. 초면은 문구·키워드만, 세부는 펼침으로.
5. 내보내기 버튼 없음. 개인정보 입력칸 없음(회사명·직무명·단어만).

데이터를 고칠 일이 있으면 `surgery/data/`를 직접 고치지 말고 노션 `자료실 섹터 보드` 20번 페이지에 적어 주세요. 피클이 스키마와 함께 고칩니다.

## 6. 출처·라이선스

- 데이터: **자체 설계 프레임워크 · 직업상담 일반 원칙** (외부 데이터셋 미사용)
